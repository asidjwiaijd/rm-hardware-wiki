# RM 硬件组文档风格

## 核心原则

### 1. 消除 AI 味

**删掉这些词**：总的来说、值得注意的是、在当今时代、综上所述、本文将深入探讨、帮助大家更好地了解、具有重要意义、首先需要明确的是、与此同时、温馨提示、需要注意的是、简单来说。

**替换方式**：

- 直接陈述事实，不加铺垫
- 短句，一句一个信息点
- 保留具体信息（型号、数值、步骤），删除空泛描述
- 有确切数据时删掉"约""大概""可能"

**示例**：

- ❌ "本文将从多个维度详细介绍电源链路的相关内容，帮助大家更好地理解。"
- ✅ "本页说明第三周电源板的设计约束和选型要点。"
- ❌ "需要特别注意的是，同学们务必在规定时间内提交打样。"
- ✅ "打样有周期，第二、三周的板子越早提交越好。"

### 2. 保持培训文档语气

**用**："可以参考""建议提前""通常""如果你……""一般"。

**避免**："务必""暖心""宝子们""冲就完了""闭眼入""强烈推荐购买"。

**删除**：

- 冗余的开头结尾（"各位同学好……""最后，欢迎大家加入……"）
- 括号里的冗余解释
- 过时内容（标着"此节已过时"的就直接删）
- 删除线内容 —— 有用就直接说，没用就删掉

### 3. 安全与风险内容必须严谨

**高风险主题**：焊接、锂电池、通电调试、高压、实验室规章、器材借用。

- 用 `:::danger` 或 `:::warning` 标注，不要用 `:::tip`
- 不开玩笑，不用 emoji
- 给出具体后果（"碰到皮肤是立刻烫伤"）而不是"请注意安全"
- 涉及具体参数（温度、电压、容量）的要标来源或写"以数据手册为准"

**低风险主题**（软件安装、学习方法、采购建议）：语气可以轻松一点，但仍然克制。

## Markdown 规范

### 加粗

**可以加粗**：必须或禁止的行为、硬性约束、容易混淆的关键区分。

**不要加粗**：数字、日期、型号、一般性说明、整段文字、列表标签。

### `==高亮==`

用于：搜索关键词、需要视觉突出但不属于警告的内容、长句里的次要提醒。

一段里最多用一两处，用多了等于没用。

### Emoji

可以用：`:::details` 标题里一个、首页 features 的图标、侧边栏顶级标题。

不要用：连续多个、严肃警告块里、依赖梗才能看懂的地方。

### 提示块

| 容器 | 用途 |
| --- | --- |
| `:::tip` | 实用建议、经验 |
| `:::info` | 补充说明、背景、"为什么这么选" |
| `:::warning` | 具体风险或后果 |
| `:::danger` | 人身安全、器材损坏 |
| `:::details` | 折叠长内容（长表格、完整流程、模板） |

嵌套时外层用四个冒号 `::::`，内层用三个。

### 路径与标题

- 用 `→` 表示操作路径：`STM32CubeMX→Clock Configuration`
- 用 `《...》` 表示官方通知或文档标题
- 芯片型号写全：`STM32F103C8T6`，不写"103"

### 标点

- 中文正文用中文标点（，。！？）
- 括号用半角 `()`，前后不留空格
- 列表项末尾不加句号

## 结构模式

### 页面拆分

页面过长时拆成子页面，主页面只留核心信息和链接。参考 `docs/environment/` 的拆法。

### 列表与表格

- 3 项以下用无序列表
- 需要对比、有多个维度时用表格（参数说明、选型对比、协议对比）
- 表格列不要超过 5 列，窄屏会难看

### 引用来源

需要标来源的：规则、考试与考核安排、费用、器件参数、官方流程、历史事件、非官方评价。

不确定时：用脚注 `[^1]` 标来源，或写"通常""以当年通知为准"，或用 `<Note>需要验证</Note>` 标出来。

`<Note>` 是临时占位。长期存在的存疑内容应该改成带来源的脚注。

## 工作流程

1. 读目标文件，判断风险等级
2. 看同目录其他文件，保持结构一致
3. 参考 `docs/training/week3.md`（约束类内容）和 `docs/environment/devtools.md`（工具说明类内容）
4. 改写时保留所有链接、脚注、组件和 frontmatter
5. 完成后检查：有 AI 味吗？过度加粗吗？Emoji 多吗？改变事实含义了吗？
6. 跑格式检查：

   ```sh
   pnpm format
   ```

## 最终检查清单

- [ ] 有 AI 味吗？
- [ ] 安全相关内容用对容器了吗？
- [ ] 保留了所有链接和脚注吗？
- [ ] 改变事实含义了吗？
- [ ] 跑过 `pnpm format` 了吗？
