# 如何学习硬件？

> 原文作者：🥭

## 前言

自从上任硬件组组长之后，大概一直就在思考这个问题。我自己固然有我所习惯的学习方法，但是否能推己及人，大概确实是有些不够确定。

但既然我能通过这条路径而学有所成，于是大概相信对应的方法固然是有可移植性的。于是在这里简要总结，希望或对各位的未来有所启发。

## 要学什么东西

提纲挈领永远是正确的决定。只有划分出明确而清晰的科技树，才能方便各位理解要学什么、为什么要学。

一个合格的硬件工程师所需的傍身之技，其科技树的第一重分支无非是**设计与实操**：

- **设计**，又细分为
  - 电路设计
  - PCB 绘制
- **实操**，又细分为
  - 焊接
  - 调试

当然，这些门类仍可细细分为三界五行，由于本文是总论性的文本，不做赘述。

除此之外，笔者自 9 月份以来一直在讨论该如何正确处理理论知识与实际应用的联系。正确的联系将对你的工作事半功倍。下文中笔者也将谈谈自己对于此等概念的理解。

## 怎么学实际应用

### 实操

实操的学习极度漫长。任何的实操都需要亲身上机的磨练。唯有实际触摸到示波器的屏幕、扭动负载的旋钮，才能真的获取实操的能力。

进一步而言，就像陈蝶衣在戏班的成长，我们完全可以一字不易地引用里面的一句台词：

> 要挨多少打才能成角啊

可以说，好的硬件工程师的实操经验来自于无数的火花飞溅。唯有 MOSFET 在手边炸响、STM32 在手中死去、电容在眼前鼓包、示波器的波形在眼前跳动，才能真正理解电路的奥妙、才能拥有充分的实操经验。

于是为了积累实操经验，你需要的就是不断不断持之以恒地画板子，调试。

### 设计

设计本身就是个庞杂的门类，各种各样的电路板大相径庭，于是设计自然形态各异。但是无论何种构型，对刚入门的你而言，无一例外自然都是晦涩难懂的天书。那么怎么读懂学懂设计呢？

以笔者之见，大约可分为以下几步。

#### 一、不求甚解地抄原理图

首先，之所以要求抄原理图需**不求甚解**，其意旨或非要求各位永远不求甚解。只是对于刚接触的新领域，其未解的知识实在过分浩瀚。试图全部弄懂再继续，实在是千头万绪一团乱麻，于是入手的抓手无处可寻；那不消说，自然而然就因为畏难而放弃了。这也是无数人放弃的本质原因。

于是不顾一切原理、埋头效仿鸵鸟，本质是为你找到一个抓手。**无脑抄，以抄为入门的第一步。**

#### 二、一边抄 layout，一边读懂基本电路构成

但是上文笔者有言：**“其意旨或非要求各位永远不求甚解”**。当你抄完一块板子，往往就有了第一步，也生发出无穷的疑问：为什么要这样设计？这个设计有什么用？为什么要这样配置引脚？

于是我们便谈到了第二步：**一边抄 layout，一边读懂基本电路构成。**

layout 与画原理图不同。画原理图时，对于各个路径的本质其实无需过分关注——无论是大功率、动辄 10A 的功率回路，又或是电流可以忽略不计的 20mA 信号回路，其在原理图的呈现都是绿线一条。然落实到 layout，则是截然不同的境界了。倘若以 10mil 的细细的蓝线试图承载 10A 的庞然大物，也只会如细弱的萤草面对轰然天风。于是 layout 时确要搞清各个回路的基本作用，那么这便是你解答抄原理图所抄出的疑问的时刻了。

以一块所有硬件组梯队都耳熟能详的 MP2329 为例：抄原理图时，你或许不甚清楚缘何电感要 4.7µH 的功率电感，5×4mm 的尺寸相比小小的芯片堪称庞然大物，似乎 0603 的小小贴片电感也有相同的效用。然当你开始 layout、开始了解原理时，你便茅塞顿开：因为电感所在的回路是 Buck 的功率回路，电感即为储能元件。倘若选之过小，大概只有轰然一声看到烟花的结果。

> **“四月的电感花火，落下的速度是秒速五厘米”**（雾）

于是通过抄 layout，至少你就理解了 Buck 的基本构成、电感的基本用处。

#### 三、抄完试图做出个性化修改，借此深入了解

于是当你优秀地完成前两步，你便有了基本的入队能力：让你抄板子，你能抄出来了。下面又迎来了下一个问题：怎么深入学习？

那就来做自定义修改罢~

是谓：**“抄完试图做出个性化修改，借此深入了解”**。

试举一例：通过抄我的开源，你可以使用 LM5148 与 MP9931 完成 24V 降 12V。那假如要改变降压电压呢？假如我说要减小纹波呢？

于是自定义设计轰轰烈烈鼓荡。那么为了自定义设计，你开始仔细翻阅佶屈聱牙的数据手册，无数英文字母在你眼前咆哮；但恭喜你，你看到了怎么计算不同输出电压的公式，你看到了怎么确定纹波，你知道了要算一下、要用更大的电感。恭喜你：通过第一次的自定义修改，Buck 你已然有了一点点深入的了解了。

#### 四、不断迭代进而越学越深

当然，自定义修改亦是由浅入深。于是随着深入，你将会了解越来越多的设计要素：刚开始只是反馈回路，第二次或许就是开关频率，第三次或许就是补偿网络、前馈电容了，或许再接下来你就能说出 COT 的控制构成，和诸如与 ESR 的配合了。

上述种种，是谓**“不断迭代进而越学越深”**。

当然，这个过程要求的是好奇心的驱动。诸如当看到 MP9931 的 mode 选择，有好奇心的你就应该去搜搜为什么不同 mode 对应不同的特点，这些 mode 反映到电感电流又意味着什么。**善用 AI**，将你的问题通通抛诸于它，它是你最好的老师。至于现实里、课堂里的老师？

bless you（笑）

## 哪些 sb 公式、理论是我需要的

好吧，终于谈到了笔者矛盾非常的一个点。现实工程不可脱离知识，但是过于掉书袋又会使实际工程碍手碍脚。或许在学校看来，你需要先系统性学习知识、再行开展应用。有用吗？不做评价。

但是就笔者的实际经验，大概或许并非需要先完备地了解一切理论才可以开展应用。以笔者之见：**先放开那些令人作呕的公式罢**，你的第一步不要被理论、公式束缚。但是在上文提到的深入了解的过程中，请开始你的知识学习。

---

知识的意义在于以第一性原理帮你改进你的板子，作为你坚实的基础。

- **没有知识的板子是没有灵魂的**，无法改进的；倘若遇到问题，你只会孤立地以设计经验改进，但对缘何如此修改一无所知
- **相反，拥有知识的板子是有灵魂的**，能够改进的；倘若遇到问题，你就可以以第一性原理分析问题，知道为什么要修改，甚至知道修改的边界条件是什么

**举一个现实的例子。** 如果不知道 FCCM 和 PSM 的模式对应什么 MOS 的状态，你只死记硬背 FCCM 是持续的电流、而 PSM 不是，那么突然有人让你的板子可以应付反电动势，你将一无所知，丈二和尚。

然而若是已知 FCCM 是上下管总有一个 MOS 一直导通、PSM 或有一个 MOS 断开，那么当有人让你的板子可以应付反电动势，你就知道了要让 MOS 一直导通，于是采用 FCCM 的改进便昭然若揭。

于是笔者对于理论的态度，总结而言便是：

**以工程为主线。** 先大胆抛开理论做！当你改进板子遇到问题时，适度深究背后涉及的理论知识，借此不断用完备的理论充实自己的第一性原理能力。

以工程为主线，让学理论作为围绕工程进行的伴生品，大概如此。
