# 第 3 周 · 培训讲义

:::danger
前排提醒：实际设计时请以所用器件的官方手册为准。
:::

## 本节目标

[《培训讲义 1》](/training/note1)解决"认识元器件"，[《培训讲义 2》](/training/note2)解决"把元器件连成一块能工作的板子"。但一块板子若不能与别的板子、别的模块交换数据，它的功能便无从发挥。本节讨论**有线通信**，即通过少量信号线在各模块之间传输数据。

本节侧重**物理层与硬件实现**——电平是多少、谁来驱动、要不要终端电阻、线怎么走、地怎么接；至于"报文里第几个字节代表什么"，属于电控组的工作范围。

| 环节   | 目标                                               |
| ------ | -------------------------------------------------- |
| 分层   | 理解通信协议的分层结构，明确硬件负责的是哪一层     |
| 信号   | 能区分单端与差分、异步与同步、开漏与推挽           |
| 协议   | 掌握 UART、I2C、SPI、CAN 四类主总线的硬件要点      |
| 收发器 | 知道每一种总线需要什么外围器件、什么电平、什么终端 |
| 设计   | 能独立完成一次通信接口的原理图与 PCB 设计          |
| 示例   | 能用 STM32 HAL 库写出四种协议的收发代码            |

:::tip 硬件与软件的分工
同一个协议，软件工程师关注帧、字段与校验，硬件工程师关注电平、驱动能力、阻抗与回流路径。

两者描述的是同一件事的不同层面。通信失败时，软件排查代码，硬件排查电平与接地；本节只讨论后者，即如何让信号在铜皮上尽可能完整地走完全程。
:::

## 通信协议的分层

任何一套通信系统都可以按**分层**来理解。以最通行的三层划分：

| 层         | 职责                           | 举例                                         | 归属     |
| ---------- | ------------------------------ | -------------------------------------------- | -------- |
| 物理层     | 电平、编码、驱动、线缆、连接器 | TTL 电平、差分对、$120\,\Omega$ 终端、双绞线 | **硬件** |
| 数据链路层 | 帧结构、寻址、仲裁、校验       | UART 的起始位、CAN 的 ID 仲裁、CRC           | 软硬交界 |
| 应用层     | 数据的含义                     | 电调转速值、IMU 姿态、遥控通道               | 电控     |

硬件工程师主要负责**物理层**，同时需要读懂数据链路层，才能判断某个参数是否会影响信号质量。

:::info 为什么先讲分层
初学者最容易犯的错误，是把"协议不通"归结为"程序写错了"。但一个协议要在两根线上跑，就必须先满足物理层的一切要求：电平对得上、驱动带得动、阻抗匹配、地连在一起。**物理层不成立时，再正确的程序也跑不通。** 分层的目的，就是让你在排查时知道该先看哪一层。
:::

## 信号的四种基本形态

在逐一介绍具体协议之前，先理清四个基本概念。它们决定了每一种总线的电气特性与拓扑形式。

### 单端与差分

**单端（Single-Ended）**信号用**一根线对地**的电压表示逻辑：

$$
V_{logic} = V_{signal} - V_{GND}
$$

**差分（Differential）**信号用**两根线之间的电压差**表示逻辑：

$$
V_{logic} = V_+ - V_-
$$

![单端信号：以地为参考，高电平约 1 V，虚线为 VH 与 VL 门限](/note3/v2-a362c3c6c881339ae57470b90053ec1c_r.jpg)

![差分信号：D+ 与 D− 反相翻转，以两根线之间的电位差表示逻辑](/note3/v2-16f1b96ca58c17d025c6f30945f121a0_r.jpg)

差分传输的两个关键优势：

- **抗共模干扰**：外界干扰同时叠加在两根线上，做差时相互抵消。这是差分总线能够拉长距离、能够在强干扰环境中工作的根本原因
- **回流明确**：差分对的返回电流流经**另一根差分线**，不经地平面，因此地平面上的干扰对信号影响很小

|          | 单端                         | 差分                           |
| -------- | ---------------------------- | ------------------------------ |
| 参考对象 | 地                           | 另一根信号线                   |
| 抗干扰   | 差，受地电位差与共模噪声影响 | **好**，共模干扰在做差时被抵消 |
| 线数     | 每路信号 1 根（另加地）      | 每路信号 2 根                  |
| 典型协议 | UART、I2C、SPI、RS-232       | RS-485、**CAN**、以太网、USB   |
| 典型距离 | 几十厘米至数米               | 数十米至上千米                 |

:::warning 差分对必须并行走线
差分的抗干扰能力来自**两根线受到相同的干扰**。若两根线走不同的路径，受到的干扰不再相同，做差后残留的差值会直接混入信号。

因此差分对必须**紧密并排走线、等长、尽量保持间距不变**，这是差分原理成立的前提。
:::

:::tip 为什么必须用双绞线
双绞线使两根线依次交换位置，任何外部耦合都在一个绞距内被平均掉，这是差分抗干扰能够成立的前提。若改用两根平行散线，共模抑制随之消失，距离一长误码率便急剧上升。
:::

### 异步与同步

- **异步（Asynchronous）**：收发双方没有共享的时钟线，靠事先约定的**波特率**对齐。UART、RS-485 属此类；代价是双方时钟必须足够接近，且每帧都要花额外的位用于"对齐"
- **同步（Synchronous）**：有一根独立的**时钟线**，每一位都由时钟沿界定。I2C、SPI 属此类；代价是多一根线，好处是不需要严格的波特率匹配，速率也能做得更高

### 全双工与半双工

- **全双工**：收发各有一条独立通路，可以同时收发。UART（TX/RX 各一根）、SPI（MOSI/MISO 各一根）
- **半双工**：收发共用一条通路，同一时刻只能有一个方向传输。I2C（SDA 一根）、RS-485（一对差分线）、CAN（一对差分线）

### 点对点、主从与多主

| 拓扑         | 说明                                   | 典型协议          |
| ------------ | -------------------------------------- | ----------------- |
| 点对点       | 只有两个节点                           | UART、RS-232、SPI |
| 主从         | 一个主机发起，多个从机应答，需**寻址** | I2C、RS-485       |
| 多主（广播） | 任意节点都可主动发起，需**仲裁**机制   | CAN               |

多主总线的难点在于**冲突处理**，即两个节点同时发起发送时的处理方式。CAN 采用**非破坏性仲裁**（见后文），这是 CAN 与 RS-485 最本质的差别之一。

## 逻辑电平

物理层的一切讨论都建立在一个基础上：**高低电平究竟是多少伏**。

### TTL 与 CMOS 阈值

数字输入存在一道明确的**门限**，并非在电压中点处翻转：

| 参数                           | 含义                         |
| ------------------------------ | ---------------------------- |
| $V_{IH}$（**输入**高电平下限） | 高于此值才**保证**被识别为高 |
| $V_{IL}$（**输入**低电平上限） | 低于此值才**保证**被识别为低 |
| $V_{OH}$（**输出**高电平下限） | 输出高时**保证**不低于此值   |
| $V_{OL}$（**输出**低电平上限） | 输出低时**保证**不高于此值   |

关键在于 **$V_{OH} > V_{IH}$ 且 $V_{OL} < V_{IL}$**，接口才能可靠工作。$V_{IH}$ 与 $V_{IL}$ 之间那一段则是**不确定区**。

![5 V TTL、5 V CMOS、3.3 V LVTTL、2.5 V CMOS 与 1.8 V CMOS 的 V_OH、V_IH、V_IL、V_OL 对比](/note3/v2-1550a2594ea11a55ccf665a1a3f8eadd_r.jpg)

两类常见的输入结构：

| 输入类型 | 阈值定义方式                   | 5 V 供电下的典型值 |
| -------- | ------------------------------ | ------------------ |
| TTL      | 固定绝对电压                   | $V_{IH} \ge 2.0$ V |
| CMOS     | 按电源比例（典型 $0.7V_{DD}$） | $V_{IH} \ge 3.5$ V |

:::info 一个反直觉的结论：3.3 V 可以驱动 5 V 的 TTL 输入
很多人凭直觉认为"3.3 V 输出带不动 5 V 输入"，这在 **TTL 输入**下是错的：TTL 的门限是**绝对的 2.0 V**，与它自己的电源无关。3.3 V 输出远高于 2.0 V，因此**当接收端是 TTL 输入时，3.3 V 可以直接驱动 5 V 系统**。

但若接收端是**纯 CMOS 输入**（阈值 $0.7 V_{DD} = 3.5$ V），3.3 V 就落在不确定区，通信将时好时坏——这种"偶尔能通"的故障最难排查。

**因此判断电平兼容性时，须查对方的手册，不能凭电压数字直接比较。**
:::

### 反向的电平问题：5 V 进 3.3 V

反过来，**5 V 输出接进 3.3 V 输入**必须谨慎：5 V 通常超过 3.3 V 器件的绝对最大输入电压，轻则钳位、重则永久损坏。

例外是标注为 **5 V 容忍（FT，Five-volt Tolerant）** 的引脚。STM32 的许多 IO 属于此类，手册的引脚表会标明 `FT`。**但 FT 只保证"能承受 5 V、能识别高低"，不保证驱动能力，也不保证所有复用功能都容忍 5 V。**

### 电平转换的常用手段

| 方案         | 适用场景              | 代价                                   |
| ------------ | --------------------- | -------------------------------------- |
| 电阻分压     | 5 V → 3.3 V，低速单向 | 上升沿变缓、有静态功耗，仅适合极低速   |
| 串联限流电阻 | 引脚有内部钳位        | 依赖内部钳位二极管，长久工作可靠性存疑 |
| 专用转换芯片 | 双向、高速            | 成本与器件占用，需注意其速率限制       |

分压方案的取值即 $V_{out} = V_{in} \cdot \dfrac{R_2}{R_1 + R_2}$。例如 5 V 分压到 3.3 V，取 $R_1 = 1\,\text{k}\Omega$、$R_2 = 2\,\text{k}\Omega$，得 $V_{out} = 3.33$ V。

:::tip 分压方案不能用于双向总线
分压电阻把信号"压"下去的同时也削弱了驱动能力，只能单向使用。I2C 这类双向总线的 SDA 在两个方向上都要被驱动，分压网络会同时拖慢两个方向的边沿，因此须采用 MOS 双向转换电路或专用芯片。
:::

### 推挽与开漏

- **推挽（Push-Pull）**：输出级由上下两个管子组成，**主动**输出高电平与低电平。速度快、驱动能力强，但**两个推挽输出不能直接连在一起**——一个要输出高、另一个要输出低时，上下管直通，大电流将烧毁器件
- **开漏（Open-Drain）／开集（Open-Collector）**：输出级只有一个下拉管，**只能主动拉低**，高电平靠**外部上拉电阻**拉起来

![开漏结构与上拉电阻：器件内部只有下拉管，只能拉低，高电平由 R_p 上拉得到](/note3/1ae311ed3af09331e72317a5c9278347.png)

开漏结构支持**线与（Wired-AND）**逻辑：只要**任何一个**节点拉低，总线即为低；**所有**节点都释放，总线才被上拉为高。这一性质实现了"任何节点都可以拉低总线、但没有节点能强行拉高总线"的语义，**I2C 与 CAN 的仲裁机制都建立在其上**。

|              | 推挽                      | 开漏                     |
| ------------ | ------------------------- | ------------------------ |
| 高电平来源   | 器件内部主动输出          | **外部上拉电阻**         |
| 多个输出并联 | **禁止**（会直通烧毁）    | 允许（线与逻辑）         |
| 速度         | 快                        | 受上拉电阻与总线电容限制 |
| 典型协议     | SPI、UART、CAN 收发器内部 | I2C、SMBus               |

## UART（TTL 串口）

### 帧结构

UART 是**异步**串行接口，没有时钟线，靠双方约定的**波特率**对齐每一位。一帧的构成如下：

| 段     | 位数              | 电平                           |
| ------ | ----------------- | ------------------------------ |
| 空闲   | —                 | **高**                         |
| 起始位 | 1                 | **低**（由高变低，即"下降沿"） |
| 数据位 | 5 / 6 / 7 / **8** | 先低位后高位（LSB First）      |
| 校验位 | 0 或 1            | 奇校验 / 偶校验 / 无           |
| 停止位 | 1 / 1.5 / 2       | **高**                         |

![UART 帧结构：空闲位为高，起始位拉低，随后是 LSB 在前的 8 位数据、校验位与停止位](/note3/v2-a07dbe7612783cc4220a24c0e3a1aa62_r.jpg)

常见的 `115200-8-N-1` 表示：波特率 115200、8 位数据、无校验、1 位停止位。

:::tip 为什么起始位是低电平
空闲电平为高，使得**线路断开**（悬空、被上拉）时的状态与"空闲"一致，不易被误判为数据；起始位再用一个"高变低"的下降沿宣告一帧开始，接收端检测到这个下降沿后才启动内部的位采样。**这也是为什么两个设备必须共地**：不共地时接收端看到的电平是浮动的，"下降沿"无从谈起。
:::

### 波特率与位时间

波特率即每秒传输的位数（此处波特与比特等价）：

$$
T_{bit} = \frac{1}{f_{baud}}
$$

$115200$ bps 时：

$$
T_{bit} = \frac{1}{115200} \approx 8.68\,\mu\text{s}
$$

MCU 内部的 UART 通常以 $16$ 倍波特率的时钟**过采样**，并在每位的**中点**采样，以避开边沿处的不稳定。这解释了为什么波特率误差可以被容忍一部分，但绝不能太大。

**一帧 $10$ 位中只有 $8$ 位是有效数据**，因此传输效率：

$$
\eta = \frac{8}{10} = 80\%
$$

加上校验位则为 $8/11 \approx 72.7\%$。UART 是一种**开销很大**的接口，它的价值在于简单。

:::warning 波特率误差的容忍度只有百分之几
收发双方的波特率不可能完全一致（晶振精度、MCU 分频取整都会带来偏差）。累计误差会把采样点从中点逐渐推离，误差足够大时就会采错位——表现为**偶发的乱码**。工程上的经验是**双方各自误差应控制在 $\pm 2\%$ 以内**。
:::

### 接线与共地

TTL 串口的接线的规则：**A 的 TX 接 B 的 RX，A 的 RX 接 B 的 TX，并且两边的 GND 必须连在一起。**

| 错误接法             | 现象                                   |
| -------------------- | -------------------------------------- |
| TX 接 TX、RX 接 RX   | 双方同时驱动，无接收方，完全不通       |
| **不共地**           | 时通时不通，或完全不通，且波形一塌糊涂 |
| 电平不匹配（见前文） | 器件损坏，或落在不确定区导致偶发错误   |

:::danger 不共地是串口故障的首要原因
两块板子各自供电时，两者之间没有共同的参考点，"高"与"低"就都失去了意义，接收端看到的电压可能是任意值。

**排查串口不通时，第二步（仅次于检查 TX/RX 是否交叉）就是量一下两边 GND 之间的电压。** 若不为零，先解决共地问题。
:::

### STM32 示例代码

以下使用 STM32 HAL 库。`HAL_UART_Init()` 只负责配置**外设本身**，引脚的复用、时钟与波特率时钟源由 CubeMX 生成的 `HAL_UART_MspInit()` 完成，工程中不必手写。

```c
UART_HandleTypeDef huart1;

void uart_init(void)
{
  huart1.Instance        = USART1;
  huart1.Init.BaudRate   = 115200;            /* 必须与对端一致 */
  huart1.Init.WordLength = UART_WORDLENGTH_8B;
  huart1.Init.StopBits   = UART_STOPBITS_1;
  huart1.Init.Parity     = UART_PARITY_NONE;
  huart1.Init.Mode       = UART_MODE_TX_RX;   /* 全双工 */
  HAL_UART_Init(&huart1);
}

void uart_demo(void)
{
  uint8_t txbuf[4] = {0x01, 0x02, 0x03, 0x04};
  uint8_t rxbuf[4];

  /* 参数：句柄 / 缓冲区 / 长度 / 超时(ms) */
  HAL_UART_Transmit(&huart1, txbuf, sizeof(txbuf), 100);
  HAL_UART_Receive(&huart1, rxbuf, sizeof(rxbuf), 100);
}
```

三种收发方式按开销递增：**阻塞式**（`HAL_UART_Transmit` / `HAL_UART_Receive`）在传输期间独占 CPU，只适合小数据量与调试；**中断式**（`..._IT`）立即返回，在 `HAL_UART_RxCpltCallback()` 中处理数据，是控制周期内的常规做法；**DMA** 则用于数据量大或速率高的场合。

:::tip 接收中断需要注意的一点
`HAL_UART_Receive_IT()` 是**一次性**的：回调触发后接收即停止，必须在回调里再次调用它才能继续接收下一批数据。否则会出现"只能收到第一帧"的现象。
:::

## I2C

I2C 是板内通信的主力，几乎每一块 RM 主控板上都会用到。

### 结构

I2C 只有两根线：

- **SCL**：串行时钟
- **SDA**：串行数据

两根线都是**开漏**结构，**都必须接上拉电阻**，由主机/从机共同驱动。总线上可以挂多个主机与多个从机，每个从机有唯一的**地址**（标准 7 位）。

![I2C 典型拓扑：多个主机与从机共用 SDA、SCL，两根线各接一个上拉电阻到 VDD](/note3/image-20261001005804195.png)

| 模式     | 速率       |
| -------- | ---------- |
| 标准模式 | $100$ kbps |
| 快速模式 | $400$ kbps |
| 快速+    | $1$ Mbps   |
| 高速模式 | $3.4$ Mbps |

### 起始与停止条件

I2C 不需要额外的片选线，靠**特殊的电平组合**界定一帧的开始与结束：

- **起始条件（START）**：**SCL 为高时，SDA 由高变低**
- **停止条件（STOP）**：**SCL 为高时，SDA 由低变高**

因为数据位只在 **SCL 为低**时变化、在 **SCL 为高**时保持稳定，所以"SCL 为高期间 SDA 发生变化"这一组合在正常数据传输中**不会出现**，正好可以拿来当控制信号使用。

![I2C 时序：起始条件下的 SDA 跳变、7 位地址帧与 R/W 位、ACK 位、数据帧与停止条件](/note3/image-20261001005904145.png)

### 上拉电阻的取值

上拉电阻 $R_p$ 的取值同时受**上下两个方向**的约束：

**上限：由上升时间决定。** 总线存在寄生电容 $C_b$（走线、引脚、器件），上拉电阻与它构成 RC 充电回路：

$$
\tau = R_p \cdot C_b, \qquad t_r \approx 2.2\, R_p C_b
$$

I2C 规范对上升时间有明确上限（标准模式 $1000$ ns，快速模式 $300$ ns）。若 $R_p$ 过大，边沿过缓，采样点上的电平还没升到位，从机就会读到错误的位。

**下限：由灌电流能力决定。** 输出低电平时，节点必须把上拉电阻送来的电流全部吸入：

$$
R_{p(min)} = \frac{V_{DD} - V_{OL(max)}}{I_{OL}}
$$

I2C 规范规定 $I_{OL}$ 一般不超过 $3$ mA，以 $V_{DD} = 3.3$ V 代入，$R_{p(min)} \approx 1.1\,\text{k}\Omega$。

:::tip 手上没有示波器时怎么取上拉电阻
按经验取值即可：$100$ kbps 用 $4.7\,\text{k}\Omega$，$400$ kbps 用 $2.2\,\text{k}\Omega$。

**若通信在 $400$ kbps 下不稳定、降到 $100$ kbps 就正常，则多数是上拉电阻偏大、边沿过缓。** 把 $4.7\,\text{k}\Omega$ 换成 $2.2\,\text{k}\Omega$ 通常即可解决。

若上拉改小后仍无改善，则应怀疑**总线电容过大**（器件太多、走线太长）。
:::

:::warning I2C 的总线电容上限是 400 pF
这是由规范的驱动能力反推出来的硬性限制。I2C 的设计初衷就是连接**同一块板上**的几个器件，因此走线要短、器件要少——**把 I2C 引出板外走排线**，是初学者常见的错误。
:::

### 为什么 I2C 需要仲裁与时钟同步

虽然 RM 中基本都是单主机，但理解 I2C 的多主机制有助于明白它为什么采用开漏：

- **时钟同步**：多个主机的 SCL 通过"线与"叠加，**谁的低电平最长谁说了算**，即低速主机自动拖慢时钟
- **仲裁**：多个主机同时发送时，逐位比较 SDA。**一旦某个主机发现自己想输出高、而总线上实际是低，它就退出**——因为这说明有另一个主机正在发送优先级更高的数据

**仲裁不会破坏数据**：败方退出时总线上的数据保持完整，胜方甚至不会察觉曾有节点参与竞争。这被称为**非破坏性仲裁**。

### STM32 示例代码

HAL 库的 `HAL_I2C_Mem_Read` / `HAL_I2C_Mem_Write` 会自动完成 START、发送从机地址、发送寄存器地址等一整套时序，无需手工操作。

```c
/* HAL 要求传入左移一位后的 8 位地址 */
#define IMU_ADDR  (0x68 << 1)

uint8_t who_am_i;

/* 读：句柄 / 从机地址 / 寄存器地址 / 地址宽度 / 接收缓冲 / 长度 / 超时 */
HAL_StatusTypeDef st =
  HAL_I2C_Mem_Read(&hi2c1, IMU_ADDR, 0x75, I2C_MEMADD_SIZE_8BIT,
                   &who_am_i, 1, 100);

/* 写：除方向外参数与读一致 */
uint8_t val = 0x00;
HAL_I2C_Mem_Write(&hi2c1, IMU_ADDR, 0x6B, I2C_MEMADD_SIZE_8BIT,
                  &val, 1, 100);
```

:::tip 用返回值就能判断故障类型
`HAL_I2C_Mem_Read` 的返回值直接对应某一类故障：

- `HAL_ERROR`：通常是**从机没有应答（NACK）**，检查地址是否写错、器件是否供电
- `HAL_TIMEOUT`：总线被某个节点**拉死**，SDA 或 SCL 持续为低电平
- `HAL_OK`：时序正常
  :::

### 常见故障

:::danger I2C 的三种典型故障

- **两根线都是低电平**：某个节点把线拉死。常用解法是主机发送 $9$ 个时钟脉冲，把从机内部的移位寄存器走完，使其释放总线
- **两根线都是高电平**：检查**上拉电阻是否漏画**，或器件地址是否写错
- **偶尔出错、高速率时更严重**：优先怀疑**上拉电阻偏大**或**总线电容超标**

**排查顺序：先量上拉电阻，再量总线静态电平是否都为高。**这两步能覆盖大半故障。
:::

## SPI

SPI 是板内**高速**通信的首选。它用更多的线换来了更高的速度和更简单的时序。

### 四根线

| 线      | 全称                 | 方向                      |
| ------- | -------------------- | ------------------------- |
| SCK     | Serial Clock         | 主机 → 从机               |
| MOSI    | Master Out, Slave In | 主机 → 从机               |
| MISO    | Master In, Slave Out | 从机 → 主机               |
| CS / SS | Chip Select          | 主机 → 从机（**低有效**） |

SPI 是**同步全双工**总线：SCK 提供时钟，MOSI 与 MISO 各自独立，因此**发送与接收同时进行**。即使只希望读取数据，每次读取也必然同时写出一位，这是 SPI 的固有特性。

### 无寻址，靠片选

SPI **没有地址机制**。挂多个从机时，每个从机各占一根 CS；主机拉低哪一根 CS，就表示与哪个从机通信。

代价是**引脚数量随从机数量线性增长**：挂 $n$ 个从机就要 $n$ 根 CS。因此 SPI 连接的从机通常只有两三个。

:::warning 片选空闲时必须为高
CS 为**低有效**，因此空闲时**必须被上拉或由主机驱动为高**。

若 CS 悬空，从机会因受干扰而随机被选中，表现为"未被操作却向总线输出数据"，进而干扰真正在通信的器件。**在多从机的 SPI 总线上，一根悬空的 CS 足以让整条总线失效。**
:::

![SPI 总线示例：一个主机以 SCLK、SDO、SDI 与三个从机相连，用 CS1~CS3 分别选中](/note3/image-20261001010021184.png)

### 四种模式：CPOL 与 CPHA

SPI 有时间上的两种自由度，组合出四种模式：

- **CPOL（时钟极性）**：空闲时 SCK 是高还是低
- **CPHA（时钟相位）**：在**第一个**还是**第二个**时钟沿采样

| 模式 | CPOL | CPHA | 采样沿 |
| ---- | ---- | ---- | ------ |
| 0    | 0    | 0    | 上升沿 |
| 1    | 0    | 1    | 下降沿 |
| 2    | 1    | 0    | 下降沿 |
| 3    | 1    | 1    | 上升沿 |

:::danger 主从模式不一致时，现象是"全零"或"全高"
若主机配置为模式 0、从机为模式 1，数据将在错误的时刻被采样。典型现象是**读到的寄存器全为 0 或全为 0xFF**，而时钟线与数据线上明明有波形。

**这类故障容易被误判为器件损坏或接线错误。**判断方法是：用示波器观察 SCK 空闲时的电平（确定 CPOL），再观察第一个跳变沿之后数据是否稳定（确定 CPHA），并与手册标注对照。**SPI 通信不通时，应首先检查模式设置。**
:::

### 与 I2C 的对照

|          | I2C                     | SPI                          |
| -------- | ----------------------- | ---------------------------- |
| 线数     | $2$ + 上拉              | $4$（每多一个从机多一根 CS） |
| 双工     | 半双工                  | **全双工**                   |
| 驱动方式 | 开漏，**需上拉电阻**    | **推挽**，无需上拉           |
| 寻址     | 有地址                  | 无地址，靠片选               |
| 速率     | 最高数百 kbps 至数 Mbps | 可达数十 Mbps                |
| 适用场合 | 低速、器件多、引脚紧张  | 高速、器件少、数据量大       |

:::tip 选型的一句话总结
**器件多、速度低、引脚紧张 → I2C；器件少、速度高、数据量大 → SPI。**

IMU 同时提供两种接口时**优先选 SPI**：速率更高（可达 $10$ Mbps），不会因总线带宽限制控制频率，也无需为上拉电阻费心。
:::

### STM32 示例代码

```c
/* 模式 0（CPOL = 0，CPHA = 0）的配置要点 */
hspi1.Init.Mode              = SPI_MODE_MASTER;
hspi1.Init.Direction         = SPI_DIRECTION_2LINES;    /* 全双工 */
hspi1.Init.DataSize          = SPI_DATASIZE_8BIT;
hspi1.Init.CLKPolarity       = SPI_POLARITY_LOW;        /* CPOL = 0 */
hspi1.Init.CLKPhase          = SPI_PHASE_1EDGE;         /* CPHA = 0 */
hspi1.Init.BaudRatePrescaler = SPI_BAUDRATEPRESCALER_16;
HAL_SPI_Init(&hspi1);

/* 读一个寄存器：最高位为 1 表示读 */
uint8_t txbuf[2] = {0x80 | 0x00, 0x00};
uint8_t rxbuf[2];

HAL_GPIO_WritePin(CS_GPIO_Port, CS_Pin, GPIO_PIN_RESET);  /* 拉低片选 */
HAL_SPI_TransmitReceive(&hspi1, txbuf, rxbuf, 2, 100);    /* 全双工收发 */
HAL_GPIO_WritePin(CS_GPIO_Port, CS_Pin, GPIO_PIN_SET);    /* 释放片选 */
```

:::warning HAL 不会自动控制片选
`HAL_SPI_Transmit` / `HAL_SPI_TransmitReceive` **只负责搬运数据，不控制 CS**，片选必须由程序手动拉低与拉高。**CS 未拉低时，从机不会响应主机的任何操作。**
:::

## CAN

CAN（Controller Area Network）是 RM 车身网络的主干，电机、超电与主控之间的通信几乎全部通过 CAN 完成。它的设计目标即车载环境：**强干扰、多点、实时、可靠**。

### 物理层：差分信号

CAN 使用一对差分线 **CAN_H** 与 **CAN_L**：

![CAN 总线状态：显性位时 CANH 约 3.5 V、CANL 约 1.5 V，隐性位时两线均约 2.5 V](/note3/image-20261001010721297.png)

| 状态          | $V_{CANH}$ | $V_{CANL}$ | $V_{diff} = V_{CANH} - V_{CANL}$ |
| ------------- | ---------- | ---------- | -------------------------------- |
| 显性位（$0$） | 约 $3.5$ V | 约 $1.5$ V | 约 $2.0$ V                       |
| 隐性位（$1$） | 约 $2.5$ V | 约 $2.5$ V | 约 $0$ V                         |

接收端的判据（门限带有回差）：

- $V_{diff} > 0.9$ V → 判为**显性**
- $V_{diff} < 0.5$ V → 判为**隐性**
- 介于两者之间 → **不确定**

:::info 显性位与隐性位的驱动方式
显性位是**主动驱动**出来的，隐性位则是收发器**释放总线**后由终端电阻把两根线拉回同一电位。因此多个节点同时驱动时，只要有一个节点驱动显性，总线就呈显性，**这是 CAN 仲裁的物理基础**，与 I2C 的开漏"线与"同理。**注意 CAN 的逻辑 $0$ 是显性、逻辑 $1$ 是隐性，与通常的直觉相反。**
:::

### 终端电阻

CAN 速率高、总线长，必须按**传输线**处理。当信号沿导线传播到末端而**无处可去**时，能量会**反射**回来，与后续信号叠加，造成波形畸变与误码。反射的严重程度由反射系数描述：

$$
\Gamma = \frac{Z_L - Z_0}{Z_L + Z_0}
$$

其中 $Z_0$ 是电缆的特征阻抗，$Z_L$ 是终端负载。显然：

- 当 $Z_L = Z_0$ 时，$\Gamma = 0$——**没有反射**，这就是"阻抗匹配"
- 当 $Z_L \to \infty$（开路）时，$\Gamma = 1$——全反射
- 当 $Z_L = 0$（短路）时，$\Gamma = -1$——全反射，极性相反

标准的 CAN 双绞线，特征阻抗 $Z_0 \approx 120\,\Omega$，因此在总线**两端**各接一个 $120\,\Omega$ 电阻即可实现匹配。并联后总线等效负载为 $60\,\Omega$，**该值是正常值而非故障**。

![CAN 的两种终端方案：标准终端（CANH 与 CANL 间一个 120 Ω）与拆分终端（两个 60 Ω 串联，中点经电容接地）](/note3/image-20261001010806958.png)

:::warning 终端电阻的四个常见错误

- **只接一端**：另一端仍会全反射，匹配效果显著下降
- **接了很多个**：并联后远小于 $120\,\Omega$，负载过重，差分电平被压低到门限以下
- **接在中间节点上**：这构成分支终端，而非总线终端
- **完全不接**：短距离低速率时看似可用，一旦提速或拉长便立即出错，**现象具有欺骗性**
  :::

:::danger 终端电阻是 CAN 故障的首要排查项
CAN 通信异常时，**第一件事是用万用表量 CAN_H 与 CAN_L 之间的电阻（断电测量）**：

- 约 $60\,\Omega$ → 两端终端电阻齐全，正常
- 约 $120\,\Omega$ → **只有一端有终端电阻**，另一端缺失
- 远大于 $120\,\Omega$ → **两端都没有**
- 远小于 $60\,\Omega$ → 挂的终端电阻过多，或总线短路
  :::

### 位时序与采样点

CAN 是异步总线，每一位被划分为若干**时间份额（TQ）**：

$$
T_{TQ} = \frac{1}{f_{TQ}}, \qquad T_{bit} = N_{TQ} \cdot T_{TQ}, \qquad f_{baud} = \frac{1}{T_{bit}} = \frac{f_{TQ}}{N_{TQ}}
$$

一个位时间由四段构成：

| 段       | 作用                                 |
| -------- | ------------------------------------ |
| 同步段   | 固定 $1$ 个 TQ，用于与总线边沿对齐   |
| 传播段   | 补偿收发器与线缆的物理延时           |
| 相位段 1 | 与传播段合并可调，**其末端即采样点** |
| 相位段 2 | 用于重同步时的延长                   |

采样点位置：

$$
\text{采样点} = \frac{1 + N_{Prop} + N_{P1}}{N_{TQ}} \times 100\%
$$

![CAN 位时间分解：同步段、传播段、相位段 1 与相位段 2，以及采样点所处的位置](/note3/c8f442b1bbc8439d867cbcb878ff40ab.png)

**举例**：图中位时间的分段为同步段 $1$、传播段 $6$、相位段 1 为 $5$、相位段 2 为 $7$，共 $19$ 个 TQ，采样点位于：

$$
\frac{1 + 6 + 5}{19} \times 100\% \approx 63.2\%
$$

图中这一例的采样点偏早，仅作结构示意。实际配置应落在后文给出的 $75\% \sim 87.5\%$：取 $f_{TQ} = 16$ MHz、$N_{TQ} = 16$，分段为同步段 $1$、传播段 $6$、相位段 1 为 $7$、相位段 2 为 $2$（相位段 1 与传播段合并即 BS1 $= 13$ 个 TQ），则 $T_{bit} = 1\,\mu$s、对应 $1$ Mbps，采样点为 $87.5\%$——这正是后文代码所用的配置。

:::warning 采样点应落在 75%~87.5%
采样点太靠前，信号尚未稳定；太靠后，留给重同步的余量不足。

**当总线上各节点的采样点不一致（尤其是分属不同厂家）时，长距离、高速率下就会出现偶发错误**——这是"单独测都正常、连在一起就出错"的常见原因之一。

RM 的 CAN 一般跑 $1$ Mbps，线长应控制在 $40$ m 以内；车上的线长远小于此，**因此实际瓶颈在于接线与终端电阻，而不在速率**。
:::

### 仲裁：非破坏性

CAN 是多主总线，任意节点都可以在总线空闲时发起通信。多个节点同时发起时，靠 ID **逐位竞争**：

- 节点在发送的同时**监听总线**
- 若自己发出隐性（$1$）、而总线上是显性（$0$），说明有更高优先级的节点在发送 → **立即退出**
- **ID 数值越小，优先级越高**

由于退出的节点只是失去总线，**已经发出的显性位不会被破坏**，胜方甚至感知不到竞争，这就是"非破坏性"的含义。**CAN 的 ID 既是地址，也是优先级。**

### 帧类型与数据长度

| 帧类型 | 作用                           |
| ------ | ------------------------------ |
| 数据帧 | 发送数据（最常用）             |
| 远程帧 | 请求具有相同 ID 的节点发送数据 |
| 错误帧 | 节点检测到错误时发出，通知全网 |
| 过载帧 | 接收方尚未就绪，请求延时       |

数据帧的字段结构大致为：**帧起始 → 仲裁段（ID）→ 控制段（数据长度）→ 数据段 → CRC 段 → ACK 段 → 帧结束**。

CAN 2.0 的**数据段最长 8 字节**；CAN FD（Flexible Data-rate）扩展了数据长度与速率，但**RM 现有生态基本仍为经典 CAN**。

:::info 一帧 8 字节的容量
RM 的电机控制报文携带的是一组转速与电流设定值，8 字节足以一次广播四台电机的控制量，**这正是 CAN 能用一条报文同时驱动四台电调的原因**。这属于数据链路层与应用层的配合，硬件工程师了解其存在即可。
:::

### 收发器

MCU 的 CAN 控制器输出的是**逻辑电平**，不能直接接到差分线路上，中间必须有**收发器（Transceiver）**：

| 器件    | 说明                                 |
| ------- | ------------------------------------ |
| TJA1050 | 经典型号，早期 RM 主控与电调大量使用 |
| TJA1051 | 低功耗替代                           |
| SIT1042 | 国产替代，参数兼容                   |

多数 RM 电调（如 M3508 的 C620、GM6020）**已把收发器集成在板上**，外部只需接 CAN_H / CAN_L 与终端电阻。

:::warning 收发器的供电与使能引脚
部分收发器有独立的 `VCC` 与 `STB` / `EN`（使能）引脚。**使能引脚悬空时收发器可能进入待机状态，总线无输出**。

这是原理图上极易漏掉的一根线：**信号线与数据线都画了，唯独使能引脚没处理。** 排查 CAN 无输出时，除了终端电阻，也要确认收发器的供电与使能脚。
:::

### STM32 示例代码

波特率由**预分频**与**位时序**共同决定，配置必须与上一节的位时间分段对上。以 APB1 $= 48$ MHz、$1$ Mbps 为例：预分频取 $3$，得 $f_{TQ} = 16$ MHz；位时间取 $16$ 个 TQ，采样点落在 $87.5\%$。

```c
/* 1 Mbps 的位时序：BS1 = 13 TQ，BS2 = 2 TQ
   位时间 = 1 + 13 + 2 = 16 TQ → T_bit = 1 us → 1 Mbps
   采样点 = (1 + 13) / 16 = 87.5%                     */
hcan1.Init.Prescaler     = 3;
hcan1.Init.Mode          = CAN_MODE_NORMAL;
hcan1.Init.SyncJumpWidth = CAN_SJW_1TQ;
hcan1.Init.TimeSeg1      = CAN_BS1_13TQ;
hcan1.Init.TimeSeg2      = CAN_BS2_2TQ;
HAL_CAN_Init(&hcan1);

/* 滤波器：只放行标准 ID 0x201 的报文 */
CAN_FilterTypeDef filter = {0};
filter.FilterMode           = CAN_FILTERMODE_IDMASK;
filter.FilterScale          = CAN_FILTERSCALE_32BIT;
filter.FilterIdHigh         = 0x201 << 5;      /* 左移 5 位对齐 */
filter.FilterMaskIdHigh     = 0x7FF << 5;
filter.FilterFIFOAssignment = CAN_RX_FIFO0;
filter.FilterActivation     = ENABLE;
HAL_CAN_ConfigFilter(&hcan1, &filter);
HAL_CAN_Start(&hcan1);

/* 发送：标准帧 0x200，8 字节 */
CAN_TxHeaderTypeDef tx_hdr = {0};
uint32_t tx_mailbox;
uint8_t  txbuf[8] = {0};

tx_hdr.StdId = 0x200;          /* 数值越小，优先级越高 */
tx_hdr.IDE   = CAN_ID_STD;
tx_hdr.RTR   = CAN_RTR_DATA;
tx_hdr.DLC   = 8;              /* 经典 CAN 最长 8 字节 */
HAL_CAN_AddTxMessage(&hcan1, &tx_hdr, txbuf, &tx_mailbox);

/* 接收 */
CAN_RxHeaderTypeDef rx_hdr;
uint8_t rxbuf[8];

if (HAL_CAN_GetRxFifoFillLevel(&hcan1, CAN_RX_FIFO0) > 0) {
  HAL_CAN_GetRxMessage(&hcan1, CAN_RX_FIFO0, &rx_hdr, rxbuf);
  /* rx_hdr.StdId 即报文来源，rxbuf 中为转速、电流等数据 */
}
```

:::tip CAN 代码里最容易出错的两处

- **滤波器位对齐**：`FilterIdHigh` 存的是 ID 的**高 16 位**，ID 必须**左移 5 位**才能对齐（`0x201 << 5`）。未对齐时滤波器要么全部放行、要么全部滤除，表现为"收不到任何报文"
- **忘记 `HAL_CAN_Start()`**：配置完滤波器与波特率只完成了初始化，**不启动 CAN 外设则收发均无效**
  :::

### RM 中的应用

CAN 是 RM 车身网络的主干，典型用途包括：

| 用途       | 说明                                    |
| ---------- | --------------------------------------- |
| 电机控制   | M3508 / M2006 / GM6020 等电调，$1$ Mbps |
| 超级电容   | 主控与超电管理板之间的状态与控制        |
| 主控间通信 | 多块主控板之间的数据交换                |
| 板间通信   | 主控与分电板、与自定义功能板            |

:::tip CAN 通信排查的四步法
按顺序走完这四步，绝大多数 CAN 故障都能定位：

1. **量电阻**：断电，量 CAN_H 与 CAN_L 之间的电阻，应为约 $60\,\Omega$
2. **量共地**：确认所有节点共地，且地线上没有较大的电位差
3. **看波形**：示波器差分探头（或两通道相减）观察 $V_{diff}$，显性应达到约 $2$ V，隐性应接近 $0$
4. **查 ID 与波特率**：确认所有节点波特率一致（$1$ Mbps），且 ID 无冲突

**顺序不能颠倒**：先量电阻与共地，再上电看波形。
:::

## 其他常见接口

### RS-232

RS-232 是早期的串行标准，特点鲜明：

- **单端**传输，以地为参考；采用**负逻辑**：逻辑 $1$ 为 $-3 \sim -15$ V，逻辑 $0$ 为 $+3 \sim +15$ V
- 摆幅大（约 $\pm 12$ V），因此**噪声容限很大**，比 TTL 串口抗干扰得多；代价是需要正负电源（现代芯片用内部电荷泵产生），功耗与体积都不小
- 点对点，需要专门的收发器芯片（如 MAX3232）完成 TTL 与 RS-232 电平的互转
- 综合以上，**RM 车内几乎见不到 RS-232**

### RS-485

RS-485 把 RS-232 的单端传输改为**差分**，同时改善了抗干扰能力与传输距离，是工业与车载环境中最常见的串行总线之一。

| 特性       | 说明                                                            |
| ---------- | --------------------------------------------------------------- |
| 传输方式   | **差分**（A / B 两根线，或用 D+ / D- 表示）                     |
| 双工       | 两线制半双工，四线制全双工                                      |
| 拓扑       | 多点总线，标准 32 节点（采用 1/8 单位负载的收发器可达 256）     |
| 差分电平   | 逻辑 $1$ 约为 $V_{AB} \le -200$ mV，逻辑 $0$ 约为 $\ge +200$ mV |
| 共模范围   | $-7 \sim +12$ V，允许两端地电位有较大差异                       |
| 终端电阻   | **总线两端各 $120\,\Omega$**（理由见 CAN 一节）                 |
| 距离与速率 | $100$ kbps 约 $1200$ m；$1$ Mbps 约 $40$ m，**两者不可兼得**    |

:::info 为什么"距离与速率不可兼得"
线缆对高频成分有衰减，总线越长，可用带宽越低。工程上有一条粗略的经验边界：**线长（m）× 速率（bps）不超过 $10^8$ 量级**。

按此估算，$1200$ m 约 $83$ kbps、$40$ m 约 $2.5$ Mbps，与实际可用的 $100$ kbps 与 $1$ Mbps 是同一数量级。**该式足以用来快速判断方案是否荒诞，具体数值仍须以器件手册为准。**
:::

RS-485 是**半双工**总线，收发共用一对差分线，因此收发器上有一个 **DE（发送使能）** 引脚，由 MCU 的 GPIO 控制方向：

```c
/* RS-485：发送前拉高 DE，发送完成后立即拉回低电平释放总线 */
HAL_GPIO_WritePin(DE_GPIO_Port, DE_Pin, GPIO_PIN_SET);
HAL_UART_Transmit(&huart1, txbuf, len, 100);
HAL_GPIO_WritePin(DE_GPIO_Port, DE_Pin, GPIO_PIN_RESET);
```

:::warning DE 拉回过早会截断最后一个字节
`HAL_UART_Transmit` **在数据写入发送寄存器后即返回**，此时最后一个字节可能仍在移位输出中。若立刻把 DE 拉低，该字节将被截断。

正确做法是**等待发送完成标志（TC，Transmission Complete）**，或开启 DMA 传输并在传输完成回调中翻转 DE。
:::

### PWM

严格来说 PWM 属于**信号形式**而非"协议"：以脉冲宽度表示量值，周期固定（舵机为 $20$ ms，脉宽 $0.5 \sim 2.5$ ms）。优点是**简单**，任何 MCU 都能读取；缺点是**独占线路**，一根线只能传一路信号。RM 中用于舵机、部分电调与灯光控制。

### 以太网与 USB

- **以太网**：差分对（$100$ / $1000$BASE-T），**变压器隔离**，图传与视觉模块与主控之间常用。硬件上需要专门的 PHY 芯片与网络变压器，阻抗控制要求 $100\,\Omega$ 差分
- **USB**：差分对，差分阻抗 $90\,\Omega$，速率从 $1.5$ Mbps 到数百 Mbps 不等，常用于**调参与下载**，少数场合用于与视觉模块通信

这两者的共同点是**对差分阻抗与走线质量要求很高**。板内布局时应严格按手册给出的阻抗与长度匹配要求执行，本节不展开。

### 单总线

以 WS2812（灯珠）与 DS18B20（温度传感器）为代表：**一根线既传数据又供电或取电**，靠严格的时序编码区分 $0$ 与 $1$。优点是省线，缺点是**时序窗口极窄，对中断与走线长度都敏感**，灯带走线不宜过长，且应避免与 PWM 大电流回路平行。

## 硬件设计要点

把以上协议抽象出来，通信接口的硬件设计无非六件事。

### 一、电平匹配

- 确认双方的电平标准（TTL / CMOS / RS-232 / RS-485 / 差分），并分清对方是**绝对阈值**还是**比例阈值**（见前文 3.3 V 驱动 5 V 的讨论）
- 需要转换时优先用**专用芯片**，分压电阻仅用于极低速单向场合

### 二、上拉与终端

| 接口   | 需要什么                                                      |
| ------ | ------------------------------------------------------------- |
| I2C    | SDA 与 SCL **各一个上拉电阻**，$2.2 \sim 4.7\,\text{k}\Omega$ |
| SPI    | 每个从机的 **CS 上拉**（空闲为高）                            |
| RS-485 | 总线**两端各 $120\,\Omega$**                                  |
| CAN    | 总线**两端各 $120\,\Omega$**                                  |

**上拉电阻与终端电阻是电路的组成部分，而非可选装饰。** 它们漏画时的现象往往与程序错误极为相似。

### 三、差分走线与阻抗

用于差分总线（RS-485、CAN、以太网、USB）：

- 两根线**紧密并排**，间距保持恒定
- **等长**（长度差应远小于信号波长），布线尽量少打过孔
- 在**接口器件附近**完成终端匹配，走线不要先拉出去再拐回来
- 若用四层板，优先保证**参考地平面完整**，不要被其他走线割裂

### 四、共地与回流

这是最容易被忽略、也最常导致难以定位的故障的一环。

- 所有互联的通信节点**必须共地**
- 信号的回流路径应尽量短——**在四层板上，让信号层紧邻地平面**（见[《培训讲义 1》](/training/note1)的叠层原则）
- 若两端地电位差较大（长线、大电流场合），应改用**隔离**方案，而非直接连接

:::danger 大电流地线上的"地弹"
把通信的地与大电流回路的地共用同一段铜皮时，大电流流过这段铜皮的压降会叠加在信号地上，使接收端看到的"高"与"低"整体漂移。

**表现为：电机一转，通信就出错**，这是 RM 车上最典型的疑难杂症之一。解决办法是**通信地与功率地分开走线、单点汇合**（用 $0\,\Omega$ 电阻在同一点连接，见[《培训讲义 1》](/training/note1)）。
:::

### 五、保护

通信接口大多暴露在接插件上，是 ESD 与浪涌的第一入口：

- **TVS**：抑制瞬态高压，应紧靠连接器放置
- **串联小电阻**：限制 ESD 电流、改善阻抗
- **共模电感**：抑制共模干扰，用于差分总线
- **自恢复保险丝**：防止外部短路或误接

**保护器件必须紧靠连接器。** 放在器件一侧会使长段走线暴露在瞬态威胁之下（见[《培训讲义 2》](/training/note2)的布线要点）。

### 六、线材与连接器

| 场合          | 建议                                           |
| ------------- | ---------------------------------------------- |
| 板内板间短距  | 排针 / 排母，注意间距与极性                    |
| 车载通信      | 双绞线，CAN_H / CAN_L 成对，**不要用普通散线** |
| 长线 / 强干扰 | 屏蔽线，屏蔽层**单端接地**                     |

:::tip 屏蔽层为什么单端接地
屏蔽层若两端都接地，而两端地电位不同，**屏蔽层本身就会流过地电流**，反而成为较大的干扰源；单端接地则使其成为等电位面，将干扰引到一端，不形成回路。**看似更保险的两端接地，在长线场合往往效果最差。**
:::

## 小结

有线通信的硬件部分可以归纳为三条：

- **电平要匹配**：$V_{OH} > V_{IH}$、$V_{OL} < V_{IL}$，并且要分清对方是绝对阈值还是比例阈值
- **驱动方式要明确**：开漏必须配**上拉**，差分长线必须配**终端**，收发器必须处理**使能与供电**
- **地要干净**：共地是所有通信的前提，通信地不应与功率地混用

具体到各协议，其硬件要点如下：

| 协议   | 硬件要点                                   |
| ------ | ------------------------------------------ |
| UART   | 共地、TX/RX 交叉；波特率误差预算仅百分之几 |
| I2C    | 依赖上拉电阻，阻值决定通信成败             |
| SPI    | 依赖片选，模式必须与从机一致               |
| CAN    | ID 即优先级；终端电阻是首要排查项          |
| RS-485 | 工业差分串口，距离与速率不可兼得           |

**这些接口的"不通"，绝大多数源于上述物理条件之一未满足，而与程序无关。** 调试时应先量电阻，再看波形，最后才怀疑代码。
