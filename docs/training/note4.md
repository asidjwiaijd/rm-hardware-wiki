## 一、嵌入式系统与最小系统

### 什么是嵌入式系统

**嵌入式系统**指为了完成某项特定功能、而嵌在设备内部运行的计算机系统。它与我们日常使用的电脑有明显区别：

|              | 通用计算机       | 嵌入式系统                 |
| ------------ | ---------------- | -------------------------- |
| 目的         | 通用，什么都能做 | 专用，只做设计好的那件事   |
| 资源         | 内存与存储充足   | 资源有限，按需配置         |
| 与硬件的关系 | 通过驱动间接控制 | **直接控制引脚与器件**     |
| 举例         | 笔记本、服务器   | 主控板、传感器模块、路由器 |

一块嵌入式板子通常包含以下几部分：

| 组成           | 作用                      | 本节的例子                    |
| -------------- | ------------------------- | ----------------------------- |
| MCU（主控）    | 运行程序、控制一切        | STM32F103C8T6                 |
| 供电           | 为所有器件提供稳定的电压  | 5 V 输入 + AMS1117-3.3        |
| 时钟           | 给 MCU 一个准确的时间基准 | 8 MHz 晶振 + 32.768 kHz 晶振  |
| 复位与启动配置 | 让 MCU 能启动，也能被复位 | NRST 网络、BOOT0 / BOOT1      |
| 下载调试接口   | 把程序写进去、能单步调试  | SWD 排针                      |
| 板上外设       | 完成具体功能的器件        | CAN 收发器、IMU、EEPROM、屏幕 |
| 对外接口       | 与板外交换信号与电        | 排针、接线端子                |

### 什么是最小系统

**最小系统**指让 MCU 正常工作所必需的**最少**外部电路。它由五部分组成，缺一不可：

| 组成     | 作用                                      |
| -------- | ----------------------------------------- |
| 供电     | 为 MCU 提供稳定的 3.3 V 与模拟电源        |
| 时钟     | 提供 HSE 与 LSE 振荡器                    |
| 复位     | 提供 NRST 的外部网络                      |
| 启动配置 | 用 BOOT0（F103 另有 BOOT1）决定从何处启动 |
| 下载调试 | 提供 SWD 接口                             |

把这五样接好，再**把没有用到的 IO 全部引出到排针**，就得到一块**最小系统板**。

**主控板与最小系统板的区别，只在于外设的多少。** 先能做出最小系统板，此后的复杂板只是在同一套结构上增加器件。

:::tip 为什么新手要从最小系统板开始
一块板子上元件越少，出错的地方越少。最小系统板上只有 MCU 与十几颗电容电阻，如果它不能跑，问题必定出在这十几颗元件或走线上，排查范围很小。

**先让最小的一块板子跑起来，再去加外设。** 反过来做，一旦板子不工作，你将同时面对十几个 bug。
:::

### 板上供电：从 5 V 到 3.3 V

本节的最小系统板只需要一路 5 V 输入，再由一颗 **AMS1117-3.3 (SOT-223)** 把 5 V 转成 MCU 所需的 3.3 V。

**为什么这里用 LDO？** [《培训讲义 2》](/training/note2)已经得出结论：**压差越小、电流越小，越适合 LDO**。本题的条件是压差 $5 - 3.3 = 1.7$ V、板上总电流只有百毫安量级，属于 LDO 最合适的区间。LDO 外围元件极少、输出纹波小，且不需要电感，适合新手起步。

**先估算需要多少电流。** 选器件前要把板上各部分的电流加一遍：

| 负载                    | 电压  | 典型电流   | 备注                   |
| ----------------------- | ----- | ---------- | ---------------------- |
| MCU（F103C8T6，72 MHz） | 3.3 V | 30～50 mA  | 与主频、外设使能数相关 |
| 板上 IMU / 传感器 ×N    | 3.3 V | 5～20 mA   | 逐颗累加               |
| OLED / 小尺寸屏         | 3.3 V | 10～30 mA  | 全亮时更高             |
| EEPROM / Flash          | 3.3 V | 数 mA      | 写入时更高             |
| 板上 LED 指示灯 ×N      | 3.3 V | 按限流电阻 | 按全部点亮累加         |
| USB 转串口芯片          | 3.3 V | 10～20 mA  |                        |

合计通常在一百毫安上下。**取 1.5～2 倍的余量**，选一颗能稳定输出 300 mA 以上的器件即可。

**再校核发热。** LDO 上损耗的功率等于压差乘电流：

$$
P = (V_{IN} - V_{OUT}) \times I = (5 - 3.3) \times I = 1.7 \times I
$$

100 mA 时约 0.17 W，500 mA 时约 0.85 W。功率越大，芯片越热，越需要选择封装更大、能更好散热的型号，并在 PCB 上给它留出覆铜散热。同样是 LDO，压差或电流再高一些，发热就会超出它的承受能力。

AMS1117 的外围只有电容：

| 位号      | 器件          | 取值           | 作用                             |
| --------- | ------------- | -------------- | -------------------------------- |
| $C_{IN}$  | MLCC          | 10 μF + 0.1 μF | 抑制输入端纹波，就近向芯片供电   |
| $C_{OUT}$ | 钽电容 / 电解 | 22 μF          | 稳定环路，抑制负载跳变引起的跌落 |

> [《培训讲义 2》](/training/note2)已说明，AMS1117 的环路稳定依赖输出电容的 ESR，须按手册要求选择。

### 模拟电源的分离

MCU 的模拟部分（ADC 用到）对噪声很敏感。做法是**从同一路 3.3 V 出发，经一颗磁珠分出"模拟 3.3 V"，再单独去耦后接到 VDDA**。

若把 VDDA 直接与数字 3.3 V 接在同一段铜皮上，数字电路的翻转噪声会进入 ADC 的采样结果，表现为"采到的值一直在跳"。

:::warning 不要用 IO 口给器件供电
新手常犯的一个错误，是把某根 GPIO 拉高当作电源，去给外部模块供电。

**GPIO 的驱动能力只有几毫安**，远不足以给一个模块供电；强行这样做不仅器件无法工作，还可能把引脚烧坏。**需要供电的器件，应直接从电源网络取电。**
:::

## 二、认识 STM32F103C8T6

![STM32F103C8Tx（LQFP48）的原理图符号：四边排布 GPIO 与复用功能引脚，VDD / VSS、VDDA / VSSA、VBAT 等供电引脚与 NRST、BOOT0 以黄色标出](/note4/image-20261008001541622.png)

### 它是什么样的芯片

| 项目     | 数值                      |
| -------- | ------------------------- |
| 内核     | Cortex-M3                 |
| 最高主频 | 72 MHz                    |
| 存储     | 64 KB Flash、20 KB SRAM   |
| 封装     | LQFP48（引脚间距 0.5 mm） |
| GPIO     | 37 个                     |
| 供电     | 2.0～3.6 V，通常用 3.3 V  |

:::tip 为什么选这颗芯片
资料与例程最多，价格低，功能对新手足够，**LQFP 封装可以手工焊接**。
:::

### 供电引脚

STM32 的供电引脚分几类，接法各不相同。F103C8T6 的引脚如下：

| 引脚              | 作用             | 接法                                       |
| ----------------- | ---------------- | ------------------------------------------ |
| VDD / VSS（3 对） | 数字供电与地     | 接 3.3 V，**每一对都要配一颗 100 nF 去耦** |
| VDDA / VSSA       | 模拟供电与模拟地 | 经磁珠接 3.3 V，配 100 nF 与 1 μF          |
| VBAT              | 备份域供电       | 不用时接 VDD；用纽扣电池供电时接电池正极   |

F103C8T6 在 LQFP48 封装上有三对 VDD / VSS，因此**至少需要三颗 100 nF 去耦电容**，另外再并联一颗 4.7～10 μF 覆盖低频段。

:::warning 不同型号的供电引脚并不相同
以两个常见型号为例：STM32F103 **没有 VCAP 引脚**，核心所需的约 1.8 V 由片内稳压器产生，外部无需接电容；STM32F4 系列则多出 VCAP_1 与 VCAP_2 两个引脚，**各需外接一颗 2.2 μF 电容**，漏接会导致芯片随机启动失败。

**供电引脚的种类与数量必须按所用型号的数据手册逐一核对**，凭印象照抄另一块板是一种常见的错误来源。此外，100 引脚以上的封装才单独引出 VREF+，而 F103C8T6 的 VREF+ 在内部已与 VDDA 相连。
:::

### 时钟系统

![CubeMX 的 RCC 配置：High Speed Clock（HSE）选 Crystal/Ceramic Resonator，芯片上 PD0、PD1 随即被占用为 RCC_OSC_IN 与 RCC_OSC_OUT](/note4/image-20261008001713491.png)

**时钟给 MCU 提供时间基准**：每执行一条指令、每走一步时序，都以它为准。F103C8T6 有四类时钟源：

| 时钟 | 类型         | 频率        | 用途                               |
| ---- | ------------ | ----------- | ---------------------------------- |
| HSI  | 内部 RC      | 8 MHz       | 上电时的默认时钟，精度差，仅作应急 |
| HSE  | 外部无源晶振 | 4～16 MHz   | 系统主时钟，常用 8 MHz             |
| LSE  | 外部无源晶振 | 32.768 kHz  | RTC                                |
| PLL  | 倍频器       | 由 HSE 倍频 | 产生系统时钟与 USB 所需的 48 MHz   |

**为什么要外接晶振？** 内部的 HSI 由 RC 振荡电路产生，受温度与工艺影响，误差可达百分之几；而外部石英晶振的误差通常在百万分之几十以内。**通信、定时、计时都要求准确的时钟**，因此正常工作时要切换到 HSE。

#### 负载电容

晶振手册给出的是负载电容 $C_L$，而实际接在电路上的是两颗匹配电容 $C_1$、$C_2$，两者关系为

$$
C_L = \frac{C_1 \cdot C_2}{C_1 + C_2} + C_{stray}
$$

取 $C_1 = C_2 = C$，并计入约 3～5 pF 的杂散电容 $C_{stray}$，可得

$$
C = 2 \left( C_L - C_{stray} \right)
$$

例如晶振手册给出 $C_L = 20$ pF、杂散电容按 4 pF 估计，则 $C = 32$ pF，取标准值 33 pF。常见取值：8 MHz 晶振配 2 × 18～33 pF，32.768 kHz 配 2 × 10～15 pF，**具体以手册给出的 $C_L$ 反推为准**。

**有源晶振与无源晶振**也不同：无源晶振（Crystal）只是一个石英片，需要 MCU 内部的振荡电路驱动，因此要配负载电容；有源晶振（Oscillator）内部自带振荡电路，通电即输出方波，直接接到 OSC_IN 即可，无需负载电容。

:::warning 晶振不是"接上就行"
晶振对**负载电容、走线长度与邻近干扰**都很敏感。负载电容偏差会造成频率偏差，而频率偏差会同时造成**波特率偏差、CAN 位时序偏差与 RTC 计时偏差**——这些故障最终都表现为"通信偶尔出错"，很难反查到晶振上。

PCB 上晶振必须紧靠 MCU、走线尽量短、下方不走其他信号，并在周围用接地过孔围住（见后文布局要点）。
:::

### 复位与启动配置

**复位**：NRST 为低电平复位，芯片内部已有弱上拉。外部只需在 NRST 与地之间接一颗 100 nF 电容（ST 推荐），硬件组建议再并联 10 kΩ 上拉。电容应紧靠 NRST 放置。

![CubeMX 引脚视图中的 NRST：保持默认的 Reset_State，不作为普通 GPIO 使用](/note4/image-20261008001826608.png)

![NRST 复位网络：RST 经 10 kΩ（R3）上拉到 3.3 V，再由 100 nF（C13）接到地](/note4/image-20261008001934928.png)

:::info
上电复位的实质是上电瞬间复位电容两端电压为 0 V（电容两端电压不能突变），NRST 引脚为低电平。
:::

**启动配置**由 BOOT0 与 BOOT1 共同决定，也就是"上电后从哪里开始执行程序"：

| BOOT0       | BOOT1 | 启动位置   | 用途                         |
| ----------- | ----- | ---------- | ---------------------------- |
| 0（接地）   | 任意  | 片内 Flash | 正常运行程序                 |
| 1（接 VDD） | 0     | 系统存储器 | 使用串口 Bootloader 下载程序 |
| 1           | 1     | 片内 SRAM  | 调试用，极少使用             |

标准做法是**用一只 10 kΩ 电阻把 BOOT0 下拉到地**，另留一个跳线或按键便于短接到 VDD 进入 Bootloader；BOOT1 若不用，同样下拉到地。F103 的 BOOT1 与 PB2 复用，若该引脚另有用途则需权衡。

:::danger BOOT0 不可悬空
BOOT0 悬空时，其电平由漏电流与外部干扰决定，可能在上电瞬间被判定为高，使芯片进入 Bootloader 而不运行用户程序。

**"程序下载成功却不运行"这一类故障，多数源头就在这里。** 必须用电阻给出确定电平。
:::

:::info
镊子也是一种方便短接的工具
:::

### 下载与调试：SWD

STM32 支持 JTAG 与 SWD 两种调试接口。SWD 只需两根信号线，占用引脚少，是常规选择。

| 信号        | 引脚 | 说明                   |
| ----------- | ---- | ---------------------- |
| SWDIO       | PA13 | 双向数据               |
| SWCLK       | PA14 | 时钟                   |
| NRST        | NRST | 可选，用于复位方式下载 |
| 3.3 V / GND | —    | 为调试器提供参考电平   |

排针用 2.54 mm 规格，放在**板边**并留出插拔空间，丝印标明 `3V3 / SWDIO / SWCLK / GND / NRST` 的顺序。SWDIO 与 SWCLK 上可各串一只 22～100 Ω 电阻，改善信号质量。

### 外设概览

下表列出 STM32F103C8T6 实际具备的外设及其在板上的用途。注意最后一列全部是**板上器件**，本节的讨论范围止于板边。

| 外设                | 作用                           | 板上用途                             |
| ------------------- | ------------------------------ | ------------------------------------ |
| GPIO                | 通用输入输出，共 37 个         | 按键、指示灯、使能脚、片选           |
| 高级定时器 TIM1     | 互补 PWM、死区、刹车           | 产生带死区的互补 PWM 波形            |
| 通用定时器 TIM2/3/4 | 定时中断、PWM、输入捕获        | 控制周期定时、PWM 输出               |
| 基本定时器 TIM6/7   | 只能计数并产生更新中断         | **本型号不具备**（见于更高密度型号） |
| ADC1 / ADC2         | 逐次逼近型，12 位，最高 14 MHz | 板上采样电阻与运放输出的电压采集     |
| USART1/2/3          | 异步串口                       | 调试串口、经板上电平转换芯片对外     |
| I2C1 / I2C2         | 板内低速同步总线               | 板上 IMU、EEPROM、OLED               |
| SPI1 / SPI2         | 板内高速同步总线               | 板上 IMU、Flash、屏幕                |
| CAN1                | 差分多主总线                   | **经板上的 TJA1050T 收发器**接入总线 |
| USB FS              | 全速设备接口                   | 板上 USB 座，可用作 CDC 调参         |
| DMA1                | 7 个通道                       | ADC 采样、串口收发、SPI 大块传输     |
| RTC                 | 实时时钟                       | 计时、掉电保持                       |
| IWDG / WWDG         | 独立与窗口看门狗               | 程序失控时复位                       |

其中 **DMA 属于各外设共用的搬运通道，而非独立外设**。CPU 只需给出源地址、目的地址与长度，搬运由 DMA 控制器完成，省去 CPU 逐字节等待。ADC 连续采样、串口大量收发都依赖它。

**CAN 与 USB 在 F103 上的默认引脚互相冲突**：两者的默认位置都在 PA11 / PA12。若板上两者都要用，必须把 CAN 重映射到 PB8 / PB9，见下一节。

### 引脚复用、重映射与分配

STM32 的引脚大多有多个可选功能，由**复用功能（AF）**决定当前处于哪一个；一部分外设还支持**重映射（Remap）**，可以把整组信号搬到另一组引脚上。重映射由 AFIO 外设统一管理，**使用前必须先开启 AFIO 的时钟**。

引脚分配需要遵循顺序：

1. **先列需求**：需要几路 CAN、几路 UART、几路互补 PWM、几个 ADC 通道、几条 SPI
2. **查复用表**：查阅数据手册的"复用功能映射表"，确认每个需求能落在哪些引脚上，以及有哪些重映射选项
3. **先分配强约束的引脚**：ADC 通道、定时器通道、互补输出对等对引脚有硬性要求的优先级最高
4. **再处理冲突**：同一引脚被两个需求占用即为冲突。若冲突源于默认映射，考虑用重映射错开
5. **最后填通用 IO**：普通 GPIO、指示灯、按键等对引脚无要求，用于填补空位

:::tip 引脚分配不是纯软件工作
分配结果直接决定 PCB 的走线难度。若把一对需要成对走线的信号拆到芯片两侧，或把连向同一器件的引脚散布在芯片四周，即便软件能够运行，PCB 也会被迫大量绕线，进而增加层数与长度。

**分配时应同时考虑原理图与 PCB 的可能布局。**
:::

## 三、GPIO 与定时器

上一节确定了要接哪些器件、要占哪些引脚。本节讨论这些引脚**怎么用**：先讲 GPIO 的配置，再讲最常用的外设——定时器。

### GPIO 的模式

每个 GPIO 引脚在任一时刻处于一种模式。输入与输出各四种，合计八种。配置时先分清这个引脚是**输入**还是**输出**：

| 模式     | 典型用途                                       |
| -------- | ---------------------------------------------- |
| 浮空输入 | 外部已有上拉或下拉，或需要高阻输入             |
| 上拉输入 | 按键接地，需要默认读到高电平                   |
| 下拉输入 | 按键接 VDD，需要默认读到低电平                 |
| 模拟输入 | ADC 采样引脚，此时数字部分被断开               |
| 推挽输出 | 常规输出，既能拉高也能拉低                     |
| 开漏输出 | 需要线与语义或与更高电压配合，须配外部上拉     |
| 复用推挽 | 外设驱动的输出，如 UART 的 TX、SPI 的 SCK、PWM |
| 复用开漏 | 外设驱动且需要开漏，如 I2C 的 SDA 与 SCL       |

两点联系前文：

- **开漏与推挽的区别**已在[《培训讲义 3》](/training/note3)中讨论：开漏只能拉低，高电平靠外部上拉，正因如此才有多机共享总线的"线与"语义
- **复用模式是外设引脚的必要条件**。把 UART 的 TX 配成普通推挽输出，引脚上不会有任何波形——外设根本没接到引脚上

**按键是最常见的一类用例。** 按键一端接地、一端接引脚，引脚设为上拉输入：不按下时读到高，按下时读到低。若反过来把按键接到 VDD，则应设为下拉输入。

### 使用 GPIO 的几点要求

- **未使用的引脚应当给出确定状态**：设为上拉输入或输出，不要留作浮空输入。悬空引脚的漏电与误触发会增加功耗，也会在测量时带来无从解释的现象
- **输出速度按需选择**。速度等级越高，边沿越陡、EMI 越大；除高速通信与 PWM 之外的引脚用低速度即可
- **驱动能力有限**。单个 GPIO 的拉灌电流只有数毫安，全部 GPIO 合计还有上限，不能直接驱动 LED 之外的负载，更不能用来给器件供电
- **5 V 容忍要看型号与引脚**。F103 的多数 IO 标注为 `FT`（5 V 容忍），但模拟输入引脚不在此列，具体以数据手册的引脚定义表为准
- 读写引脚用 `HAL_GPIO_WritePin` / `ReadPin` / `TogglePin`，参数依次为端口、引脚、电平

### 外部中断（EXTI）

除了在主循环里反复查询，GPIO 也可以作为**中断源**：某个引脚上的电平跳变直接触发一次中断，CPU 立刻去处理。用法上有三点必须注意。

| 项目        | 说明                                                  |
| ----------- | ----------------------------------------------------- |
| 触发边沿    | 上升沿、下降沿或双边沿，按信号特征选择                |
| EXTI 线编号 | 由**引脚号**决定，与端口无关                          |
| 冲突限制    | 同一编号只能选一个端口，PA0 与 PB0 不能同时作为中断源 |

第三点是实际配置中最容易踩到的一处：EXTI0 这条线只能连接到 A0、B0、C0 中的一个，若板上既需要 PA0 中断又需要 PB0 中断，必须改用其他引脚。**EXTI 的映射关系同样由 AFIO 管理。**

按键是最典型的用例。机械触点存在抖动，一次按下可能产生多次边沿，因此在中断或轮询中都需要**消抖**：软件延时后重新读一次，或用定时器周期采样。

### 中断与优先级

多个中断同时到来时，由 NVIC 决定谁先执行。每个中断有一个优先级，**数值越小优先级越高**。

![CubeMX 的 NVIC 中断优先级表：优先级分组取 4 bits for pre-emption priority，表中列出 SysTick、TIM1 更新中断与 USART1 全局中断的抢占优先级与子优先级](/note4/image-20261008002532527.png)

高优先级的抢占规则是：**高优先级的中断可以打断正在执行的低优先级中断**，等它执行完，被打断的那个再接着运行。优先级位还可以划分成"抢占优先级"与"子优先级"两部分，两者相同时才比较子优先级——入门阶段只需记住"数值小的先执行"即可。

优先级应**按实时性需求排序**：

- **最高**：CAN 接收、控制周期定时中断——漏掉一帧数据或错过一个周期都会直接影响控制
- **次之**：串口接收、IMU 数据就绪
- **较低**：按键、指示灯等非实时任务

中断服务函数中不应执行耗时操作（例如等待串口发送完成、刷新屏幕、软件消抖延时）。需要耗时的处理应交给主循环或定时器，中断只负责取走数据并置标志。

### 定时器：基本、通用与高级

定时器的本质是一个**由时钟驱动的计数器**：每来一个时钟脉冲加一，加到设定值就产生一次事件。按功能多少分为三类。

![CubeMX 中定时器的参数设置：Prescaler 填 72-1、Counter Period（ARR）填 1000-1，即 PSC = 71、ARR = 999；重复计数器 RCR 保持 0](/note4/image-20261008002712318.png)

| 类型       | 具备的功能                                     | F103C8T6 上对应的定时器  |
| ---------- | ---------------------------------------------- | ------------------------ |
| 基本定时器 | 只能计数，产生更新中断或触发其他外设           | TIM6、TIM7（**不具备**） |
| 通用定时器 | 计数、PWM 输出、输入捕获、输出比较、编码器接口 | TIM2、TIM3、TIM4         |
| 高级定时器 | 在通用基础上增加互补输出、死区、刹车、重复计数 | TIM1                     |

三种类型是**同一套定时器外设的功能裁剪**，而非三套独立的硬件：高级定时器具备全部功能，通用定时器去掉与功率驱动相关的部分，基本定时器只保留计数。F103C8T6 没有基本定时器，但**通用定时器同样可以只当作定时中断使用**，因此功能上并无缺失。

无论哪种类型，都有两个参数决定定时周期：

| 参数 | 名称         | 作用                           |
| ---- | ------------ | ------------------------------ |
| PSC  | 预分频器     | 把定时器时钟分频，得到计数频率 |
| ARR  | 自动重装载值 | 计数到此值后归零并产生更新事件 |

定时频率的计算式为

$$
f_{UPDATE} = \frac{f_{TIM}}{(PSC + 1)(ARR + 1)}
$$

其倒数即为中断周期。**F103 的定时器是 16 位，ARR 最大为 65535**，因此定时周期较长时应先把 PSC 取大，否则 ARR 会溢出。

除了定时，定时器还有几项常见用途：

- **PWM 输出**：把占空比写进通道的比较值 CCR（占空比为 $\text{CCR} / (ARR + 1)$），改变 CCR 即可改变占空比
- **输入捕获**：测量外部信号的频率与脉宽
- **编码器接口**：直接读取正交编码器的位置信号

### 定时器中断

最常用的定时器用法是**更新中断**：计数溢出时进入中断服务函数，执行周期性的任务（例如每毫秒读一次传感器）。在 HAL 库中的用法如下。

1. 用 `HAL_TIM_Base_Init()` 配置 PSC、ARR 与计数模式
2. 用 `HAL_TIM_Base_Start_IT()` 启动计数并使能更新中断
3. 在 `HAL_TIM_PeriodElapsedCallback()` 中处理

回调函数是**所有定时器共用**的，因此需要先判断是哪一个定时器触发，再执行对应逻辑。中断内只置标志、不做耗时工作。

:::warning 中断频率不能过高
中断频率越高，CPU 被占用的比例越大。F103 主频 72 MHz，若中断频率取到 kHz 量级而回调中又做了浮点运算或串口打印，主循环会被严重挤压。

**控制周期一般取 1 ms 或 500 μs。** 需要更高频率的定时任务，应优先考虑硬件外设（PWM、DMA、输入捕获）而非中断。
:::

### 高级定时器：互补输出与死区

高级定时器 TIM1 相比通用定时器多出三项与功率驱动直接相关的能力，这三项在[《培训讲义 3》](/training/note3)的 PWM 部分曾提及，此处给出具体含义。

| 功能       | 含义                                                          |
| ---------- | ------------------------------------------------------------- |
| 互补输出   | CH1 与 CH1N 输出极性相反的一对信号，CH2、CH3 同理；CH4 无互补 |
| 死区       | 互补的两路信号在切换时插入的延时，防止上下两个开关管同时导通  |
| 刹车       | BKIN 引脚上的有效电平会立即封锁全部输出，用于故障保护         |
| 重复计数器 | RCR，每经过 $N+1$ 个周期才产生一次更新事件，用于降低中断频率  |

**死区的作用**：互补的两路信号分别驱动上管与下管，若其中一路还没完全关断、另一路就导通，电源与地之间会被直接短路。死区就是在这两次切换之间插入的一小段"都关断"的时间。

死区时间的配置在 **BDTR** 寄存器中，由 DTG 字段决定，单位是定时器时钟周期。以 72 MHz 为例，一个时钟周期约 13.9 ns，取 DTG = 72 即得约 1 μs 的死区。**具体取多少要看开关管手册**：死区必须大于开关管的关断时间，但也不能取太大，否则会压缩有效的占空比范围。

### 示例代码

以下两段代码分别对应上面两节的用法，缩进与命名遵循本组约定。

**一、1 ms 的定时中断。** 定时器挂在 APB1 上，本节的 APB1 定时器时钟为 72 MHz：$PSC = 71$ 得到 1 MHz，$ARR = 999$ 得到 1 ms。

```c
/* 1 ms 定时中断：72 MHz / (71 + 1) / (999 + 1) = 1 kHz 的更新事件 */
void tim2_init_1ms(void)
{
  htim2.Instance         = TIM2;
  htim2.Init.Prescaler   = 72 - 1;
  htim2.Init.CounterMode = TIM_COUNTERMODE_UP;
  htim2.Init.Period      = 1000 - 1;
  HAL_TIM_Base_Init(&htim2);
  HAL_TIM_Base_Start_IT(&htim2);     /* 启动并使能更新中断 */
}

volatile uint8_t flag_1ms;

void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim)
{
  if (htim->Instance == TIM2) {
    flag_1ms = 1;                    /* 中断内只置标志，不做耗时工作 */
  }
}
```

主循环中按标志执行任务：

```c
while (1) {
  if (flag_1ms) {
    flag_1ms = 0;
    /* 控制周期任务写在这里 */
  }
}
```

**二、TIM1 的互补 PWM 与死区。** TIM1 挂在 APB2 上，定时器时钟同为 72 MHz：$PSC = 0$、$ARR = 999$ 得到 72 kHz，$CCR = 500$ 对应 50% 占空比。

```c
htim1.Instance               = TIM1;
htim1.Init.Prescaler         = 0;
htim1.Init.CounterMode       = TIM_COUNTERMODE_UP;
htim1.Init.Period            = 999;
htim1.Init.RepetitionCounter = 0;
HAL_TIM_PWM_Init(&htim1);

TIM_OC_InitTypeDef oc = {0};
oc.OCMode       = TIM_OCMODE_PWM1;
oc.Pulse        = 500;                  /* 占空比 = 500 / 1000 */
oc.OCPolarity   = TIM_OCPOLARITY_HIGH;
oc.OCNPolarity  = TIM_OCNPOLARITY_HIGH;
oc.OCIdleState  = TIM_OCIDLESTATE_RESET;
oc.OCNIdleState = TIM_OCNIDLESTATE_RESET;
HAL_TIM_PWM_ConfigChannel(&htim1, &oc, TIM_CHANNEL_1);

/* 死区：DTG = 72 时约 1 us（72 x 13.9 ns） */
TIM_BreakDeadTimeConfigTypeDef bd = {0};
bd.OffStateRunMode  = TIM_OSSR_DISABLE;
bd.OffStateIDLEMode = TIM_OSSI_DISABLE;
bd.LockLevel        = TIM_LOCKLEVEL_OFF;
bd.DeadTime         = 72;
bd.BreakState       = TIM_BREAK_DISABLE;
HAL_TIMEx_ConfigBreakDeadTime(&htim1, &bd);

HAL_TIM_PWM_Start(&htim1, TIM_CHANNEL_1);
HAL_TIMEx_PWMN_Start(&htim1, TIM_CHANNEL_1);   /* 互补通道 CH1N */
```

三个通道只需照此配置 CH2 / CH3，并各自启动对应的互补通道，即可得到三相带死区的互补 PWM。

## 四、用 CubeMX 按需求完成配置

### CubeMX 在流程中的位置

CubeMX 生成的是**初始化代码**：时钟配置、引脚复用、外设寄存器与中断使能。业务逻辑仍由人工编写。因此正确的顺序是先定需求，再定引脚，最后配时钟并生成工程；顺序颠倒会造成反复返工。

### 建立工程的步骤

1. **选择型号**：新建工程后按型号筛选，注意封装（本节的例子为 LQFP48）
2. **Pinout & Configuration**：使能外设、分配引脚、填写基础参数
3. **Clock Configuration**：配置时钟树
4. **Project Manager**：选择工具链、设置路径与代码生成选项
5. **GENERATE CODE**：生成工程

### 时钟树配置

以 STM32F103C8T6 达到 72 MHz 为例：

![CubeMX 的时钟树配置：HSE 8 MHz 经 PLLMul ×9 得到 SYSCLK 72 MHz；AHB 不分频，APB1 二分频得 PCLK1 36 MHz（其定时器时钟仍为 72 MHz），APB2 不分频得 72 MHz](/note4/image-20261008002758209.png)

各时钟域的上限与本节取值：

| 时钟域      | 上限   | 本例取值 | 说明                       |
| ----------- | ------ | -------- | -------------------------- |
| SYSCLK/HCLK | 72 MHz | 72 MHz   | AHB 预分频为 1             |
| APB1        | 36 MHz | 36 MHz   | 预分频为 2                 |
| APB2        | 72 MHz | 72 MHz   | 预分频为 1                 |
| USB         | 48 MHz | 48 MHz   | 由 PLL 输出经 1.5 分频得到 |
| ADC         | 14 MHz | 12 MHz   | 由 PCLK2 分频得到          |

两点必须记住：

- **APB 上的定时器时钟会自动二倍频。** 只要 APB 预分频不为 1，挂在该 APB 上的定时器就获得 ×2 的时钟。本例中 PCLK1 为 36 MHz，但 **APB1 的定时器时钟是 72 MHz**；APB2 预分频为 1，因此其定时器时钟同为 72 MHz。**做定时或 PWM 计算时必须以此为准，否则周期会差一倍。**
- **不同系列的参数名不同。** F1 用 PLLMUL 表示倍频系数，F4 则拆成 PLLM、PLLN、PLLP、PLLQ 四个参数，部分时钟域的上限也不同。**换型号时必须重新核对时钟树，不要照搬上一个工程的配置。**

:::warning 程序卡在时钟初始化
下载后若程序停在 `HAL_RCC_OscConfig()` 附近不再继续，多数原因是 **HSE 晶振未起振**：负载电容取值不当、晶振虚焊，或 `HSE_VALUE` 宏与板上实际频率不一致。

排查顺序为：先量晶振是否起振，再核对 `HSE_VALUE`，最后检查负载电容。STM32 另有时钟安全系统（CSS），可在 HSE 失效时自动切回 HSI 并触发中断；对 CAN 这类对位时序敏感的通信而言，时钟一旦改变必须立即停止发送，而非带着错误的时钟继续运行。
:::

### 引脚与 GPIO 的配置项

| 项目     | 可选值                    | 说明                                       |
| -------- | ------------------------- | ------------------------------------------ |
| 模式     | 输入 / 输出 / 复用 / 模拟 | 复用功能引脚必须选"复用"，ADC 引脚选"模拟" |
| 输出类型 | 推挽 / 开漏               | 开漏用于 I2C 与共享信号                    |
| 上下拉   | 无 / 上拉 / 下拉          | 输入引脚一般要给确定电平                   |
| 输出速度 | 低 / 中 / 高              | 速度越高 EMI 越大，按需选择而非一律最高    |
| 用户标签 | 自定义名称                | 生成代码后成为宏，提高可读性               |

- Toolchain / IDE 选择 `Makefile`

群主一般喜欢 Copy all library files，但别忘了把 `Drivers/` 文件夹放入 `.gitignore`。

![CubeMX 的 Code Generator 选项：选择 Copy all used libraries into the project folder，并勾选 Generate peripheral initialization as a pair of '.c/.h' files per peripheral 与 Keep User Code when re-generating](/note4/image-20261008003221508.png)

生成后的目录结构：

| 文件                           | 内容                           |
| ------------------------------ | ------------------------------ |
| `Core/Src/main.c`              | 主循环，调用各外设的初始化函数 |
| `Core/Src/gpio.c`、`tim.c` 等  | 各外设的初始化函数             |

写在区间外的手写代码会在下次生成时被覆盖。
:::

### 常见配置错误

- **把 SWD 引脚或 NRST 配置成普通 IO**
- 时钟树超限而未察觉
- 手写代码写在 USER CODE 区间之外，重新生成后被覆盖
- 复用功能引脚未选"复用"，导致外设无输出
- CAN 与 USB 同时使用时未做重映射，导致引脚冲突

:::danger 不要把 SWD 引脚配置成普通 IO
PA13 与 PA14 默认是 SWD 的 SWDIO 与 SWCLK。若在 CubeMX 中把它们改作普通 GPIO，下载后调试器将无法再连接芯片，只能靠**拉高 BOOT0 开机**或**在复位瞬间抢先连接**来抢救。

同理，把 NRST 用作普通 IO 会失去复位调试的能力。**这两个引脚在分配时应视为保留。**
:::

### 一份按需求配置的示例

需求来自前文的接口规划，落到 CubeMX 后如下。表中引脚均经过冲突检查，且全部面向板上器件。

| 需求             | 外设   | 引脚                                      | 配置要点                                             |
| ---------------- | ------ | ----------------------------------------- | ---------------------------------------------------- |
| 三相互补 PWM     | TIM1   | PA8 / PA9 / PA10，互补 PB13 / PB14 / PB15 | 死区、中央对齐                                       |
| 与总线通信       | CAN1   | PA11 / PA12                               | 位时序 1 Mbps（见[《培训讲义 3》](/training/note3)） |
| 调试串口         | USART2 | PA2 / PA3                                 | 115200、8N1                                          |
| 板上 IMU、EEPROM | I2C1   | PB6 / PB7                                 | 开漏复用，外部上拉                                   |
| 板上 IMU、Flash  | SPI1   | PA5 / PA6 / PA7，片选 PA4                 | 模式与从机一致                                       |
| 电压采样         | ADC1   | PA0 / PA1 / PB0                           | 多通道 + DMA + 规则组                                |
| 板上指示灯       | GPIO   | PC13                                      | 推挽输出，低速                                       |
| 下载调试         | SYS    | PA13 / PA14                               | SWD，**不可改作普通 IO**                             |

生成的 `main` 骨架如下。业务代码只出现在 USER CODE 区间内：

```c
uint16_t adcbuf[3];

int main(void)
{
  HAL_Init();
  SystemClock_Config();
  MX_GPIO_Init();
  MX_DMA_Init();
  MX_ADC1_Init();
  MX_TIM1_Init();
  MX_CAN1_Init();

  /* USER CODE BEGIN 2 */
  HAL_ADC_Start_DMA(&hadc1, (uint32_t *)adcbuf, 3);   /* 采样由 DMA 搬运 */
  HAL_TIM_PWM_Start(&htim1, TIM_CHANNEL_1);
  HAL_TIMEx_PWMN_Start(&htim1, TIM_CHANNEL_1);        /* 互补通道 */
  HAL_CAN_Start(&hcan1);
  /* USER CODE END 2 */

  while (1) {
    /* USER CODE BEGIN 3 */
  }
  /* USER CODE END 3 */
}
```

## 五、绘制 STM32 最小系统板

### 元件清单

| 器件         | 型号 / 参数                      | 数量   | 作用               |
| ------------ | -------------------------------- | ------ | ------------------ |
| MCU          | STM32F103C8T6（LQFP48）          | 1      | 主控               |
| 输入接口     | 5 V 排针、或端子、或 TYPE-C 座子 | 1      | 由板外提供 5 V     |
| 稳压器       | AMS1117-3.3                      | 1      | 5 V 转 3.3 V       |
| HSE 晶振     | 8 MHz 无源 + 两颗负载电容        | 1 组   | 系统主时钟         |
| 去耦电容     | 100 nF                           | 3 颗起 | 对应三对 VDD / VSS |
| 储能电容     | 4.7～10 μF                       | 1～2   | 低频去耦           |
| 模拟电源滤波 | 磁珠 + 100 nF + 1 μF             | 1 组   | VDDA               |
| 复位网络     | 100 nF + 10 kΩ                   | 1 组   | NRST               |
| BOOT 配置    | 10 kΩ 下拉 ×2 + 跳线             | 1 组   | BOOT0 与 BOOT1     |
| SWD 排针     | 2.54 mm，4～5 针                 | 1      | 下载调试           |
| 指示 LED     | LED + 1 kΩ                       | 1 组   | 电源 / 运行指示    |
| IO 排针      | 2.54 mm                          | 若干   | 引出未使用的 IO    |

:::tip
最小系统板不含任何收发器与其他板上外设。后续要增加 CAN 通信时，在 5 V 与 3.3 V 轨上各取一路电，加入 TJA1050T 与其终端网络即可（见[《培训讲义 3》](/training/note3)）。

RM 场景下很少见到 LSE 晶振。
:::

### 原理图绘制步骤

1. 放置 MCU 符号，逐项核对**封装与引脚编号**（编号画错会导致整板报废）
2. **电源与去耦**：三对 VDD / VSS 各配一颗 100 nF，再并一颗 4.7～10 μF；VDDA 经磁珠
3. **时钟**：HSE 与 LSE，负载电容按手册 $C_L$ 计算
4. **复位**：NRST 接 100 nF 到地，必要时并联 10 kΩ 上拉
5. **启动配置**：BOOT0 与 BOOT1 各经 10 kΩ 下拉，BOOT0 留跳线
6. **下载调试**：SWD 排针，标明引脚顺序
7. **指示与引出**：电源指示 LED、未用 IO 全部引出到排针
8. **电源输入**：5 V 输入端子、LDO 及其输入输出电容
9. 运行 ERC，逐条处理未连接与冲突提示

### 去耦电容的规则

- **每一对 VDD / VSS 配一颗 100 nF**，F103C8T6 即三颗
- **再在总输入并联一颗 4.7～10 μF**，覆盖低频段
- **就近放置**，距离引脚应在 5 mm 以内，位置优先于走线美观
- **走线顺序为"过孔 → 电容 → 引脚"**，使电容真正位于供电通路上
- 小容值电容用小封装（0402 / 0603），以减小等效串联电感

:::tip 为什么去耦要"先过电容再进引脚"
去耦电容的作用是为高频电流提供一条就近的回路。若走线从过孔直接进入引脚，再从引脚分支到电容，那么引脚到电容之间的那段走线电感仍留在回路中，去耦效果随之下降。

**布局上体现为：电源过孔与芯片引脚之间先落下电容，再到引脚。**
:::

### PCB 布局与布线要点

推荐 4 层叠层（见[《培训讲义 1》](/training/note1)）：**信号 / 地 / 电源 / 信号**。信号层紧邻地平面，回流路径最短。若只做两层板，则要保证地平面尽量完整，避免走线切断地平面的连续性。

| 区域     | 要求                                                 |
| -------- | ---------------------------------------------------- |
| 晶振     | 紧靠 MCU，走线短，下方禁止走线，周围用接地过孔围成岛 |
| 去耦电容 | 同层就近，置于电源过孔与引脚之间                     |
| 模拟区   | VDDA 远离开关电源、晶振与大电流回路                  |
| 电源路径 | 线宽按电流选取（见下表），必要时改用覆铜             |
| 稳压器   | 靠近输入端子，留出覆铜帮助散热                       |
| 覆铜     | 双面覆铜并加缝合过孔，使地平面连成整体               |

走线宽度的经验值（1 oz 铜厚、允许 10 ℃ 温升、外层）：

<Note>大约如此</Note>

| 电流 | 最小线宽（约） |
| ---- | -------------- |
| 1 A  | 12 mil         |
| 2 A  | 30 mil         |
| 3 A  | 55 mil         |
| 5 A  | 110 mil        |

**内层散热条件差，同样电流所需的宽度约为外层的两倍**；实际设计应再留余量，或用覆铜、多个过孔并联的方式分担。过孔的载流能力同样需要校核，必要时成排布置。

### 打样与焊接

| 封装   | 引脚间距    | 手工焊接可行性                     |
| ------ | ----------- | ---------------------------------- |
| LQFP48 | 0.5 mm      | 可焊，需用热风枪或拖焊，注意连锡   |
| QFN    | 0.5 mm      | 底部有散热焊盘，需锡膏与热风，较难 |
| BGA    | 0.8 mm 以下 | 手工不可焊，须钢网 + 回流          |

最小系统板选用 LQFP 封装，正是为了便于手工焊接与返修。投板时建议选择**沉金**工艺，焊盘平整、易于上锡；若板上没有需要阻抗控制的走线，常规工艺即可。

### 上电与调试

| 阶段     | 操作                                                                           |
| -------- | ------------------------------------------------------------------------------ |
| 上电前   | 万用表测量 3.3 V 与 GND 之间是否短路；核对稳压器与电容极性；目视检查连锡与虚焊 |
| 首次上电 | 使用**限流电源**，电流限值先从 100 mA 起                                       |
| 测电源   | 测 5 V 输入与 3.3 V 输出；观察空载电流是否合理                                 |
| 测晶振   | 用 ×10 探头轻触 OSC 引脚，确认起振；接触过重会停振                             |
| 连调试器 | 连接 SWD，读取芯片 ID                                                          |
| 下载程序 | 下载并运行第一个程序（点亮 LED）                                               |

常见故障与对应排查方向：

| 现象               | 可能原因                                 |
| ------------------ | ---------------------------------------- |
| 完全不启动         | 电源未到；封装或引脚编号画错             |
| 反复复位           | NRST 电容取值不当或走线受扰；去耦不足    |
| 无法下载           | BOOT0 或 BOOT1 电平错误；SWD 引脚被占用  |
| 频率、波特率偏差大 | 晶振负载电容不符                         |
| ADC 采样值跳动     | VDDA 未与数字电源分离                    |
| 定时周期差一倍     | 定时器时钟按 PCLK 而非二倍频后的时钟计算 |

### 检查清单

- 三对 VDD / VSS 是否各有一颗就近的 100 nF
- LDO 的输入输出电容是否按手册取值，是否靠近芯片
- 晶振负载电容是否按手册 $C_L$ 反推得到
- BOOT0 与 BOOT1 是否都有确定电平
- NRST 是否接了 100 nF
- SWD 排针是否靠板边、丝印是否清晰
- 电源路径线宽是否按电流选取
- 未使用的 IO 是否全部引出，未使用引脚是否给出确定状态
- 所用型号的供电引脚是否已逐一比对手册（如 F103 无 VCAP）

## 小结

以主控为核心设计一块板，可以归纳为三条：

- 最小系统的五件事（供电、时钟、复位、启动配置、下载调试）缺一不可
- 引脚分配先看需求，再看手册，最后考虑 PCB
- 先用 CubeMX 把需求落成配置，再开始写业务代码

各环节的要点如下。

| 环节     | 一句话要点                                       |
| -------- | ------------------------------------------------ |
| 供电     | 压差小、电流小就用 LDO；先估电流，再校核发热     |
| 最小系统 | 五件事缺一不可，BOOT0 与供电引脚是最易出错的两处 |
| GPIO     | 模式按用途选定，未用引脚要给出确定状态           |
| 定时器   | 先算 PSC 与 ARR，再谈中断与 PWM                  |
| CubeMX   | 手写代码只写在 USER CODE 区间内                  |
| 原理图   | 每对 VDD 一颗 100 nF，VDDA 经磁珠                |
| PCB      | 晶振包围、去耦就近、电源按电流给线宽             |

**最小系统板是后续所有主控板的基础。** 这一块做对之后，此后的复杂板只是在同一套结构上增加外设与接口。
